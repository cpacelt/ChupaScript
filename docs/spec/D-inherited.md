# Приложение D. Наследуемое поведение, которое хотелось бы изменить

Документ ненормативный и расхождений не содержит. **Все расхождения с ECMA-262 —
в приложении C.**

Здесь перечислено поведение, которое язык наследует от JavaScript и считает
неудачным, но воспроизводит в точности. Ни одна запись отсюда на язык не влияет:
на устройстве и в браузере всё описанное ниже работает одинаково — так, как
предписывает ECMA-262.

Запись отвечает на вопрос «почему оставлено как есть», а не «как оно устроено».
Список существует затем, чтобы решение не пересматривалось заново при каждой
встрече с этим поведением.

Переход записи в приложение C возможен только вместе с механизмом, дающим новое
поведение на Web. Пока механизма нет, запись остаётся здесь.

У каждой записи есть раздел «Доступно сейчас» — средства, снимающие часть
проблемы, не трогая поведение: статическое правило (оно отвергает тексты, а
значит остаётся сужением) либо соглашение, описанное в `docs/impl/`.

## D-1. Изменение коллекции во время её обхода

**Наблюдаемое поведение.** `for...of` по массиву на каждом шаге заново читает
`length`. Поэтому добавление элемента из тела цикла продлевает обход, а удаление
— заставляет его пропускать элементы.

```js
for (let x of items) { items.push(x); }      // не завершится никогда
for (let x of items) { items.shift(); }      // обойдёт половину
```

**Почему считаем дефектом.** Первая запись — незавершающийся цикл, то есть
исчерпание лимита и снятие единицы исполнения. Вторая молча даёт неверный
результат: ни ошибки, ни признака того, что часть данных не обработана. Ни для
той, ни для другой записи применения, в котором такое поведение требуется, не
известно.

**Чего хотим.** Чтобы обходимая коллекция была неизменна на время обхода, а
попытка её изменить давала ошибку времени исполнения. Правило «коллекция
неизменна до конца цикла» формулируется одной фразой; снимок вместо ошибки хуже
— он тоже расходится с JavaScript, но молча.

**Что мешает.** Ошибки на Web не будет: там цикл исполнит браузер по своим
правилам. Расхождение получится тем самым, ради устранения которого язык и
устроен как подмножество.

**Доступно сейчас.** Частый случай закрыт правилом `CS-EE-0019` без всякого
расхождения: вызов изменяющего метода в теле цикла отвергается, если получатель
синтаксически совпадает с обходимым выражением. Это сужение — единица
исполнения отвергается, а не переосмысляется, — поэтому инвариант сохраняется.

Правило не ловит обращение через второе имя:

```js
let a = items;
for (let x of items) { a.push(x); }
```

Отслеживать это статически означало бы вводить анализ псевдонимов, чего в
проверке нет и, скорее всего, не будет.

## D-3. Несогласованный компаратор `sort`

**Наблюдаемое поведение.** ECMA-262 требует определённого порядка только при
согласованном компараторе: он должен быть антисимметричен, транзитивен и давать
одинаковый результат при повторных вызовах на одной паре. Если компаратор этому
не удовлетворяет, порядок назван implementation-defined.

```js
items.sort((a, b) => a.rank > b.rank)          // возвращает булево, не число
items.sort((a, b) => Math.random() - 0.5)      // не воспроизводим
```

**Почему считаем дефектом.** Это единственное известное место, где два движка,
оба соответствующих ECMA-262, законно дают разные результаты на одном входе. Для
языка, инвариант которого сформулирован через совпадение с V8, такая запись
означает молчаливое расхождение платформ.

**Чего хотим.** Чтобы порядок был определён всегда — например, чтобы
несогласованный компаратор давал ошибку времени исполнения, а не произвольный
результат.

**Что мешает.** Согласованность — свойство функции на всех парах входа, а не
свойство её текста; статически она не проверяема. Проверка во время исполнения
означала бы дополнительные вызовы компаратора и всё равно неполный ответ. На Web
проверять некому: сортирует браузер.

**Доступно сейчас.** Частично закрывается составом библиотеки: `Math.random` в
неё не входит, поэтому второй пример отвергается правилом `CS-EE-0021` — как
обращение к отсутствующему члену пространства имён `Math`. Первый пример не
отвергается ничем.

Проверка типа результата компаратора статическим правилом не выражается: тело
стрелочной функции — произвольное выражение, и его тип до исполнения неизвестен.

## Как пополнять

Запись заводится, когда выполнены три условия: поведение унаследовано от
JavaScript, оно признано неудачным для задач BDUI, и его исправление требует
расхождения.

Если исправление достигается сужением — это не запись сюда, а статическое правило
и строка в `B-narrowings.md`. Если механизм воспроизведения на Web найден —
это не запись сюда, а запись в приложении C.
