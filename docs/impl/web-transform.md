# Механизм воспроизведения CS-DIV-0001 на Web

Не спецификация языка. Само расхождение определено в `docs/spec/C-divergences.md`.

## Механизм воспроизведения на Web

На Web единицу исполнения вычисляет браузер, и предписать ему не обходить
цепочку прототипов спецификация не может. Требуемое поведение обеспечивается
преобразованием исходного текста, выполняемым тем же проходом, который проверяет
статические правила (`CS-CONF-0007`).

### Вспомогательные объявления

Преобразованный текст открывается объявлением ограждающей функции:

```js
function __own(o, k) {
  return Object.hasOwn(o, k) ? o[k] : undefined;
}
```

Переменные `__t0`, `__t1`, … объявляются там, где нужны: в начале единицы
исполнения — для правил, преобразующих выражение, и самим развёртыванием — для
правил, преобразующих объявление.

Имена `__own` и `__tN` выбирает проход — так, чтобы они не встречались в
преобразуемой единице. Правила, запрещающего эти имена в исходном тексте, не
требуется.

Ограждение не подменяет диагностику: `Object.hasOwn` на `null` и `undefined`
возбуждает `TypeError` ровно там, где его возбуждает обращение к свойству в
JavaScript. Запись `undefined.k` остаётся ошибкой времени исполнения
(`CS-RT-0029`), а не превращается в `undefined`.

В таблицах ниже переменные показаны с наименьшими номерами; при вложенности
преобразуемых конструкций берутся следующие свободные, чтобы одновременно живущие
значения не делили переменную.

### Чтение свойства

| Исходная запись | После преобразования |
|---|---|
| `o.k` | `__own(o, "k")` |
| `o[e]` | `__own(o, e)` |

Порядок вычисления сохраняется: в `__own(o, e)` сначала вычисляется `o`, затем
`e` — как и в `o[e]`.

### Необязательные цепочки

Цепочка преобразуется целиком, а не по звеньям: короткое замыкание в JavaScript
отменяет всю цепочку, а не одно обращение. Запись вида `a ?. z₁ z₂ … zₙ`, где
`zᵢ` — звенья `OptionalChain`, даёт

```js
(__t0 = a) == null ? undefined : E
```

где `E` — результат преобразования `__t0 z₁ z₂ … zₙ` по остальным правилам
настоящего раздела.

| Исходная запись | После преобразования |
|---|---|
| `a?.k` | `(__t0 = a) == null ? undefined : __own(__t0, "k")` |
| `a?.[e]` | `(__t0 = a) == null ? undefined : __own(__t0, e)` |
| `a?.b.c` | `(__t0 = a) == null ? undefined : __own(__own(__t0, "b"), "c")` |
| `a?.b(x)` | `(__t0 = a) == null ? undefined : __t0.b(x)` |

Переменная здесь обязательна. Запись `a == null ? undefined : __own(a, "k")`
вычисляла бы `a` дважды, и при `a` вида `f(x)` вызов повторился бы вместе со
всеми своими последствиями.

### Цель присваивания

`o.k = v` и `o[e] = v` остаются собой: запись создаёт или заменяет собственное
свойство, цепочка на результат не влияет.

### Составное присваивание

Здесь свойство и читается, и записывается, поэтому позиция целью присваивания не
исчерпывается: ограждается чтение, запись остаётся прямой, получатель
вычисляется один раз.

| Исходная запись | После преобразования |
|---|---|
| `o.k += v` | `(__t0 = o, __t0.k = __own(__t0, "k") + v)` |
| `o[e] += v` | `(__t0 = o, __t1 = e, __t0[__t1] = __own(__t0, __t1) + v)` |

Остальные составные операторы (`-=`, `*=`, `/=`, `%=`) преобразуются как `+=`.

### Образцы

Связывание по `ObjectPattern` — это чтение свойств, поэтому образец
разворачивается в отдельные объявления:

| Исходная запись | После преобразования |
|---|---|
| `let { a, b: c } = o;` | `let __t0 = o; let a = __own(__t0, "a"); let c = __own(__t0, "b");` |
| `let { [e]: v } = o;` | `let __t0 = o; let __t1 = e; let v = __own(__t0, __t1);` |
| `for (const { a } of xs) { B }` | `for (const __t0 of xs) { const a = __own(__t0, "a"); B }` |

`ArrayPattern` преобразования не требует: он читает только целочисленные индексы,
а их цепочка прототипов не поставляет. Образцов в параметрах функций не
возникает: `FormalParameter` и `ArrowParameters` выводят только `Identifier`.

### Позиции, которые не преобразуются

**Вызываемое встроенного метода.** `items.map(f)` остаётся собой: метод в
браузере доставляется прототипом, и это как раз тот результат, который определён
разделом спецификации о библиотеке. То же для члена пространства имён:
`Math.round(x)`.

**Преобразование объекта в примитив.** `String(o)` остаётся собой. При соблюдении
`CS-EE-0022` и договора с хостом, описанного ниже, результат совпадает с
определённым в разделе спецификации о преобразованиях; чем это условие не
покрыто — в следующем подразделе.

## Что механизм не закрывает

Преобразование ограждает чтение свойства, но не преобразование объекта в
примитив. Оградить его означало бы заменить вызовами всякий `+`, всякую
подстановку в шаблонную строку и всякое сравнение, то есть переписать почти весь
текст. Поэтому `String(o)` на Web выполняет браузер по своим правилам.

Разойтись результаты могут в одном случае: у объекта есть собственное свойство с
именем `toString` или `valueOf`.

```js
dict[k] = v;                 // k пришёл из данных и равен "toString"
String(dict)                 // "[object Object]" здесь; в браузере — TypeError
```

Записью в тексте такое свойство не создать: `CS-EE-0022` отвергает эти два имени
в позиции ключа литерала, цели присваивания и цели связывания. Остаётся
вычисляемый ключ, который статически не проверяем.

Остаток закрывается договором с хостом: ключи, полученные разбором входного
JSON, при записи в объект отвергаются, если совпадают с `toString` или `valueOf`.
Проверка стоит одного сравнения на ключ и делается там, где данные и так проходят
через хост. Место договорённости — `embedding.md`, раздел 5.

До введения этой договорённости остаток открыт. Других мест, где определённое
здесь поведение на Web не обеспечено, не известно.

## Цена

Три следствия, принятые вместе с расхождением.

**CS-CONF-0010 ослаблен.** Единица исполнения остаётся корректным текстом
JavaScript, поэтому `CS-CONF-0001` сохраняется без изменений. Но совпадение
поведения обеспечивается уже не самим текстом, а текстом после преобразования:
`CS-CONF-0010` действует с оговоркой на расхождения, записанные в
`docs/spec/C-divergences.md`.

**Чтение свойства на Web стоит вызова функции.** Влияние на бюджет кадра
измеряется отдельно (раздел 12 книги, раздел спецификации об ошибках).

**Исполняемый на Web текст перестал совпадать с исходным.** Отладка на Web
показывает преобразованный текст, если конвейер не поставляет карту соответствия.

Альтернатива — оставить Web без преобразования — отвергнута: тогда `dict[key]`
давало бы функцию в браузере и `undefined` на устройстве, то есть ровно то
расхождение платформ, ради устранения которого язык устроен как подмножество.
Без преобразования расхождение не устраняется, а переносится с одного места на
другое.
