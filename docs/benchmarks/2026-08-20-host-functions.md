# Цена вызова функции хоста (задача 13)

Машина `roman-putincev` (Apple M4 Pro, 14 ядер), сборка `Release`
(`CMAKE_BUILD_TYPE=Release`, `build-rel`), коммит `4e19089` (последний
перед этой задачей). Замер — `benchmarks/host_function_benchmark.cpp`, три
бенчмарка, каждый компилирует своё выражение один раз вне цикла и
вычисляет его в цикле, как и соседние блоки `benchmarks/host_benchmark.cpp`.

## Как снят

```
cmake --build build-rel -j8
./build-rel/benchmarks/chupascript_benchmarks --benchmark_filter=Host
```

## Числа

| замер | выражение | время |
|---|---|---|
| `BM_Host_Builtin_Count` | `count(items)` | **12.2 нс** |
| `BM_Host_CallVoid` | `hostConst()` — функция хоста, ноль аргументов | **10.5 нс** |
| `BM_Host_CallString` | `hostLen('Заголовок дальше некуда')` — функция хоста, один строковый аргумент | **16.3 нс** |

(`--benchmark_repetitions=5` на тех же трёх именах дал средние 12.1 / 9.88 /
15.7 нс — тот же порядок величины, разброс `cv` 1–2%.)

## Две цены и их разность

**Цена вызова через указатель.** У языка нет билтина без аргументов
(`core/src/builtin.cpp` — у всякой записи `minArgs >= 1`), так что честной
пары «ноль против нуля» не существует в принципе; `count(items)` — самый
дешёвый билтин, возвращающий число, и это ближайшая доступная база, хотя
ему есть что переводить (один аргумент), а `hostConst()` — нечего.

Результат: **`hostConst()` дешевле `count(items)` на 1.7 нс (12.2 → 10.5,
-14%)**. Диспетчеризация через указатель на функцию хоста плюс переход
границы C API не дороже диспетчеризации билтина по индексу — она дешевле,
потому что `count` вдобавок читает глобальную переменную `items` и обходит
массив, считая его длину, а `hostConst()` не читает ничего. Число
демонстрирует не «дороговизну указателя» (гипотеза не подтвердилась), а
то, что вызов через указатель сам по себе НЕ узкое место — тяжелее то, что
билтин делает после диспетчеризации.

**Цена с одним строковым аргументом.** `hostLen(s)` отличается от
`hostConst()` ровно одним строковым аргументом — та же самая функция
хоста, тот же путь диспетчеризации, плюс распаковка одного значения через
`chupa_value_string`. Разность: **16.3 − 10.5 = 5.8 нс** на распаковку
одной строки-аргумента через границу C API — это и есть цена «коробки»:
число едет в самих байтах `ChupaValue`, строка — нет, и `chupa_value_string`
обязана её прочитать явно.

## Что не измерялось

Замер не трогает `benchmarks/host_benchmark.cpp` — файл с пятью блоками
жизненного цикла хоста (простановка переменных, компиляция и вычисление
выражений, скрипты, кадр целиком), по которым принимались решения о модели
памяти; эти замеры остаются нетронутыми и в этот документ не входят.
