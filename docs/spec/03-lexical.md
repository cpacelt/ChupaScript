# 3. Лексика

Нормативное дополнение к `grammar/lexical.txt`: правила, которые продукциями не
выражаются. Идентификаторы правил — `CS-LEX-nnnn`; примеры кода ненормативны.

Перечень того, что отвергается продукциями `lexical.txt` и `syntax.txt` по
сравнению с JavaScript, собран в `B-narrowings.md`.

## 3.1. Отбрасываемые элементы

**CS-LEX-0001.** Элементы `WhiteSpace`, `LineTerminator` и `Comment` разделяют
токены и синтаксической грамматике не передаются. Единственный их наблюдаемый
след — наличие перевода строки между токенами (CS-LEX-0003).

## 3.2. Самое длинное совпадение

**CS-LEX-0002.** На каждом шаге применяется та продукция действующей цели
разбора, которая даёт наибольшее по длине совпадение начиная с текущей позиции.

> Пояснение. Без этого правила `+=` разбирался бы как `+` и `=`, `===` — как
> `==` и `=`, `//` — как два `/`, а `leta` не отличалось бы от `let a`.
> Неоднозначности при равной длине совпадения грамматика не допускает: два
> разных токена одной длины из одной позиции не выводятся.

## 3.3. Переводы строк и точка с запятой

**CS-LEX-0003.** Между токенами `A` и `B` присутствует перевод строки, если
исходный текст между концом `A` и началом `B` содержит хотя бы одну
`LineTerminatorSequence` — в том числе входящую в `MultiLineComment`.

**CS-LEX-0004.** Автоматическая расстановка точек с запятой не производится.
Точка с запятой ставится только там, где её требует синтаксическая грамматика.

> Пояснение. Многострочный комментарий переводы строк не скрывает: в записи
> `return /* \n */ x;` перевод строки между `return` и `x` присутствует. На это
> правило опираются ограничения `[no LineTerminator here]` синтаксической
> грамматики: они сохранены, чтобы единица исполнения, смысл которой в
> JavaScript изменила бы автоматическая расстановка, отвергалась, а не
> переосмыслялась.

## 3.4. Исходный текст

**CS-LEX-0005.** Исходный текст — последовательность `SourceCharacter`,
получаемая декодированием входа из UTF-8 в кодовые единицы UTF-16.

**CS-LEX-0006.** Вход, не являющийся корректной последовательностью UTF-8, —
лексическая ошибка.

**CS-LEX-0007.** Нормализация Unicode не применяется ни к исходному тексту, ни к
значениям токенов.

**CS-LEX-0008.** `UnicodeEscapeSequence` может задать кодовую единицу из
диапазона суррогатов, не образующую пары. Значение токена в этом случае не
является корректной последовательностью UTF-16; это допустимо.

> Пояснение. U+FEFF отдельного обращения не требует: он входит в `WhiteSpace` и
> потому допустим в любой позиции между токенами, включая начало текста.

## 3.5. Значение токена

### 3.5.1. Числовой литерал

**CS-LEX-0009.** Значение `NumericLiteral` — число типа Number, ближайшее к
математическому значению записи, с разрешением ничьей в пользу чётного
(roundTiesToEven по IEEE 754). Величина, превосходящая наибольшее конечное
значение Number, даёт `Infinity`.

**CS-LEX-0010.** `NumericLiteralSeparator` на значение не влияет.

> Пояснение. Отсюда `1e400 === Infinity`, `1_000 === 1000`, а `0.1` — ближайшее
> к одной десятой двоичное значение, а не одна десятая.

### 3.5.2. Строковый литерал

**CS-LEX-0011.** Значение `StringLiteral` — последовательность кодовых единиц,
получаемая из содержимого литерала заменой каждой `EscapeSequence` по таблице:

| Запись | Результат |
|---|---|
| `\b` | U+0008 |
| `\t` | U+0009 |
| `\n` | U+000A |
| `\v` | U+000B |
| `\f` | U+000C |
| `\r` | U+000D |
| `\"` | U+0022 |
| `\'` | U+0027 |
| `\\` | U+005C |
| `\0` | U+0000 |
| `NonEscapeCharacter` | сам символ |
| `\xHH` | кодовая единица со значением `HH` |
| `\uHHHH` | кодовая единица со значением `HHHH` |
| `\u{CP}` | см. CS-LEX-0013 |

**CS-LEX-0012.** `LineContinuation` даёт пустую последовательность кодовых
единиц.

**CS-LEX-0013.** `\u{CP}` при `CP` не свыше `0xFFFF` даёт одну кодовую единицу с
этим значением; при большем `CP` — суррогатную пару, кодирующую эту кодовую
точку.

### 3.5.3. Части шаблона

**CS-LEX-0014.** Значение `TemplateCharacters` определяется правилами
CS-LEX-0011 — CS-LEX-0013 со следующим отличием: каждая входящая в текст шаблона
`LineTerminatorSequence` вида `<CR>` или `<CR><LF>` даёт одну кодовую единицу
U+000A. `<LS>` и `<PS>` переносятся без изменения.

## 3.6. Лексические ошибки

Лексическая ошибка отвергает единицу исполнения целиком: частично разобранный
текст не исполняется.

| Правило | Условие |
|---|---|
| CS-LEX-0015 | `MultiLineComment` не завершён до конца текста |
| CS-LEX-0016 | `StringLiteral` не завершён до конца строки или конца текста |
| CS-LEX-0017 | `Template` не завершён до конца текста |
| CS-LEX-0018 | символ не начинает ни одну продукцию действующей цели разбора |
| CS-LEX-0019 | непосредственно за `NumericLiteral` следует `IdentifierStart` или `DecimalDigit` |
| CS-LEX-0020 | значение `CodePoint` в `\u{…}` превышает `0x10FFFF` |
| CS-LEX-0021 | `EscapeSequence` неполна: за `\x` менее двух `HexDigit`, за `\u` менее четырёх, `\u{` не закрыта |
| CS-LEX-0006 | вход не является корректной последовательностью UTF-8 |

> Пояснение. CS-LEX-0019 отвечает сразу за два случая: `3in x` не является
> записью `3 in x`, а восьмеричная запись `0755` не является числом.
