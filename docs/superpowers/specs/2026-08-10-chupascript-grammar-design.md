# ChupaScript: грамматика языка

Дата: 2026-08-10
Статус: грамматика зафиксирована, семантика не проектировалась

## 1. Область документа

Документ фиксирует **лексическую и синтаксическую грамматику** ChupaScript —
языка для встраивания в JSON, описывающий иерархию вьюх (BDUI).

Что **не** входит в документ и решается отдельно: система типов, модель ошибок,
приведение типов, набор и семантика билтинов, модель памяти, устройство рантайма.
Открытые вопросы перечислены в разделе 6.

## 2. Граница рантайма

На вход рантайму приходит **строка с исходником**. Извлечение этой строки из JSON,
разметка полей (`@{...}` или иная) — ответственность хоста, языка не касается.

Два режима входа:

```
evalExpression(source, ctx) -> Value     // props: стартовый символ Expression
runScript(source, ctx)                   // обработчики: стартовый символ Program
```

Один лексер и один парсер, различаются только стартовым символом. Грамматика
выражения — строгое подмножество скриптовой.

**props чисты.** Присваивания недоступны в expression-режиме по построению:
присваивание — стейтмент, а стейтментов там нет. Мутирующие билтины недоступны
потому, что не возвращают значения, а использовать результат `Void`-билтина
нельзя. Свойство оставляет открытой возможность кэшировать значения props и
вычислять их лениво или вне порядка.

## 3. Лексическая грамматика

```
Whitespace  ::= ' ' | '\t' | '\n' | '\r'                    // выбрасывается
Comment     ::= '//' ( любой символ кроме '\n' )*
              | '/*' ( любой символ )* '*/'                 // без вложенности

Ident       ::= [A-Za-z_] [A-Za-z0-9_]*                     // кроме ключевых слов
NumberLit   ::= Digit+ ( '.' Digit+ )?
BoolLit     ::= 'true' | 'false'
StringLit   ::= "'" SChar* "'" | '"' DChar* '"'
SChar       ::= Escape | любой символ кроме  '  \  и перевода строки
DChar       ::= Escape | любой символ кроме  "  \  и перевода строки
Escape      ::= backslash ( backslash | ' | " | n | t )
```

Кавычка другого вида внутри литерала экранирования не требует: `'сказал "да"'`
и `"это 'цитата'"` корректны.

Правила, не выразимые в EBNF:

- Неизвестная escape-последовательность — ошибка лексера.
- Сырой перевод строки внутри строкового литерала — ошибка.
- Байты `>= 0x80` внутри строкового литерала копируются без интерпретации.
  UTF-8 самосинхронизирующийся, поэтому эмодзи и любой юникод работают без
  декодирования: байт ASCII-символа не может оказаться внутри многобайтовой
  последовательности.
- `NumberLit` конвертируется через `std::from_chars` с `chars_format::fixed`.
  `strtod` не используется — он зависит от локали.
- Знак в числовой литерал не входит: `-` всегда отдельный токен-оператор.

Ключевые слова:

```
Активные:        true  false  null

Зарезервированы: let  var  val  const  void  typeof
                 if  else  while  for  in  break  continue  do
                 function  func  return
                 this  self  new  delete  switch  case  default
                 try  catch  throw  import  export  class
```

Резерв с запасом — асимметрия цены: лишнее зарезервированное слово стоит одного
переименования, незарезервированное ломает выпущенные макеты при добавлении
конструкции в язык.

## 4. Синтаксическая грамматика

```
// ───── стартовые символы ─────
Program        ::= Statement*
Expression     ::= Ternary

// ───── стейтменты ─────
Statement      ::= Assignment | CallStmt | ';'

Assignment     ::= LValue AssignOp Expression ';'
CallStmt       ::= Call ';'

AssignOp       ::= '=' | '+=' | '-=' | '*=' | '/='
LValue         ::= Ident ( '[' Expression ']' | '.' Ident )*

// ───── выражения, от низкого приоритета к высокому (порядок Swift) ─────
Ternary        ::= LogicalOr ( '?' Expression ':' Expression )?
LogicalOr      ::= LogicalAnd ( '||' LogicalAnd )*
LogicalAnd     ::= Comparison ( '&&' Comparison )*
Comparison     ::= NilCoalesce ( CompOp NilCoalesce )?
NilCoalesce    ::= Additive ( '??' NilCoalesce )?
Additive       ::= Multiplicative ( ('+' | '-') Multiplicative )*
Multiplicative ::= Unary ( ('*' | '/' | '%') Unary )*
Unary          ::= ('!' | '-') Unary | Postfix
Postfix        ::= Primary ( '[' Expression ']' | '.' Ident )*

CompOp         ::= '==' | '!=' | '<' | '>' | '<=' | '>='

Primary        ::= NumberLit | StringLit | BoolLit | 'null'
                 | ArrayLit | ObjectLit
                 | Call | Ident
                 | '(' Expression ')'

Call           ::= Ident '(' ArgList? ')'
ArgList        ::= Expression ( ',' Expression )*

ArrayLit       ::= '[' ( Expression ( ',' Expression )* )? ']'
ObjectLit      ::= '{' ( StringLit ':' Expression
                         ( ',' StringLit ':' Expression )* )? '}'
```

Правила, не выразимые в EBNF:

- **`CallStmt` принимает только вызов билтина, не возвращающего значения.**
  `count(arr);` отдельной строкой — ошибка компиляции «результат не используется».
  Проверка выполняется после разбора по таблице билтинов; синтаксически обе формы
  идентичны.
- **Составное присваивание вычисляет цель один раз.** `arr[count(arr)-1] += 1`
  обязано вычислить индекс однократно и использовать результат и для чтения,
  и для записи. Наивное раскрытие в `x[i] = x[i] + 1` продублировало бы вызов.

## 5. Принятые решения и обоснования

| Решение | Обоснование |
|---|---|
| Вызов — выражение; `CallStmt` — обёртка над ним | Иначе `count(arr) + 1` не разбирается: операнд `+` обязан быть выражением |
| Общего `ExprStmt` нет, только `CallStmt` | `x + 1;` и `user.name;` — почти всегда опечатки (`+=`, забытое присваивание). Прецедент: Lua, Pascal, Go |
| Присваивание — стейтмент, не выражение | Убирает `if (x = 1)`; автоматически делает props чистыми от присваиваний |
| Билтины могут быть `Void` | `state.n = push(arr,1);` ловится компилятором. `Void` — внутренний тип компилятора, значением языка не является |
| Объявлений имён нет | Все данные экрана приходят с бэкенда. Из рантайма исчезают слоты, области видимости и фреймы; из семантики — правила объявления и видимости |
| Команды отделены от запросов | Мутирующий билтин возвращает `Void`, значит не может быть операндом. Выражения свободны от побочных эффектов без единой проверки; пометка «мутирует» не нужна |
| Нет `if`/`for`/`while` (пока) | Отложено. Слова зарезервированы, добавление не будет ломающим |
| Нет `return` (пока) | Без ветвления ранний выход бессмыслен. Слово зарезервировано |
| Значения в литералах — любые выражения | Ограничение «только литералы» требует параллельного набора правил, то есть *больше* грамматики. Прецедент: Lua, Starlark, CEL, Wren |
| Унарный минус — оператор | Иначе `-price` и `-(a+b)` невыразимы, а лексер становится контекстно-зависимым |
| Единственное «пусто» — `null` | Тип `Undefined` из языка исключён целиком; два вида «пусто» — источник путаницы (опыт JS) |
| Строки в обоих видах кавычек | Внутри JSON `'...'` не требует экранирования; `"..."` требует `\"` и утраивает слэши |
| Минимальный набор escape'ов | Эмодзи работают прямым символом при любом наборе — достаточно байтовой прозрачности лексера. Юникод-escape уже даёт уровень JSON |
| `NumberLit` без экспоненты | `from_chars(chars_format::fixed)`, шесть строк лексера, один символ lookahead |
| Идентификаторы только ASCII | Юникод требует таблиц UAX #31 и декодирования UTF-8; допускает визуально неразличимые имена. Кириллица в данных работает через `obj['ключ']` |
| Комментарии `//` и `/* */`, без вложенности | Скрипт в JSON часто однострочный — `//` там съел бы весь остаток молча |
| `;` обязательна, переводы строк незначимы | Без ASI; `\r` в пробельных ради CRLF |
| Пустой стейтмент разрешён | +1 строка парсера |
| Висячая запятая запрещена | `f(a, b,)` — вероятнее незаконченная правка, чем намерение |
| Добавлены `%` и `??` | Чередование в списках, неполные данные с сервера. Каждый — одна альтернатива в существующем правиле |
| Безопасного доступа нет | Чтение у `null` даёт `null`, поэтому отдельный оператор был бы неотличим от обычного |
| Цепочки сравнений запрещены | `a < b < c` разбиралось бы как `(a<b)<c` — сравнение булева с числом |
| Составные присваивания работают со всеми целями | ~10 строк компилятора на однократное вычисление цели |
| Вызов только `f(a, b)`, без `a.f(b)` | Сахар расщепил бы `obj.push` и `obj['push']`, заявленные эквивалентами. Добавить позже — не ломающее изменение |

## 6. Открытые вопросы

Семантика зафиксирована в `docs/semantics.md`; журнал решений по ней —
`2026-08-10-chupascript-semantics-design.md`. Открытым остаётся один слой:

Рантайм:

1. Время жизни буфера исходника: zero-copy строковые литералы требуют, чтобы
   он пережил скомпилированную программу.
2. Как программа получает контекст и что происходит со значениями на границе.
3. Кэш скомпилированных программ между рендерами.
4. Лимиты на недоверенный код. Сейчас без циклов программа завершается всегда,
   и время её работы ограничено размером исходника — счётчик шагов не нужен.
   Добавление `while` это свойство уничтожит.

Язык, отложенное:

5. `if`/`else`, `for-in`, `while` — слова зарезервированы.
6. `return` — слово зарезервировано.
7. Сахар `a.f(b)` — добавление не будет ломающим.
