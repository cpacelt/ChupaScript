# ChupaScript: `chupa -repl`

Дата: 2026-08-13
Статус: принято

## 1. Область документа

Интерактивная оболочка языка. Только она: ни проверки файлов, ни разбора
макетов, ни истории ввода.

Заготовка существует — `cli/main.cpp` печатает версию, корневой `CMakeLists.txt`
подключает каталог, — но содержимого в ней нет.

**Чего этот заход не делает и почему.** Режим валидации, о котором говорилось
раньше, требует читать макет: документ JSON с переменными, деревом вью и
выражениями в props. Разбор JSON в проекте отсутствует намеренно — это работа
хоста, — поэтому валидатор потянул бы либо зависимость, либо собственный парсер,
сравнимый по объёму со всем остальным CLI. Ядро оболочки — компиляция,
диагностика с указанием места, печать значений — от источника текста не зависит,
поэтому обход макета прирастает позже дешевле, чем делался бы сразу.

## 2. Что решено раньше

| Решение | Где |
|---|---|
| Состав имён программе неподвластен: язык не заводит переменных | `semantics.md` §7.1 |
| Данные ставит хост вызовом на имя, и только литералом | `2026-08-11-chupascript-data-design.md` §2 |
| Два режима: выражение и скрипт | `semantics.md` §3.1 |

| Освобождения значений по одному нет | `docs/backlog.md` B1 |

## 3. Поверхность

```
chupa -repl        запускает оболочку
chupa              печатает usage
```

Двоичный файл называется `chupa`; цель заготовки `chupascript_repl`
переименовывается. Флаг с одним дефисом.

Оболочка требует режим **явно**, префиксом строки:

```
> expr: 1 + 1
2
> script: state.n = 1;
> :vars
state = {'n': 1}
```

Строка, начинающаяся с `:`, — команда. Строка с `expr:` или `script:` — код.
Всё прочее отвергается с напоминанием, что префикс обязателен.

**Почему префикс, а не угадывание.** Грамматики двух режимов почти не
пересекаются, и автоматический выбор возможен: `1 + 1` не стейтмент, `state.n =
1;` не выражение. Но явный префикс убирает не только неоднозначность разбора, а
и вопрос «какую ошибку показать, если не вышло ни так, ни так». Сверх того он
удерживает в поле зрения различие, с которым автору макета жить: props
вычисляются выражением, обработчики выполняются скриптом.

Скрипт при успехе **молчит**: значения у него нет, а результат виден через
`:vars`. Выход — `:quit` либо конец ввода.

### 3.1 Команды

| Команда | Что делает |
|---|---|
| `:set имя = литерал` | кладёт переменную в контекст |
| `:vars` | печатает имена и значения контекста |
| `:reset` | создаёт контекст заново |
| `:help` | перечисляет команды |
| `:quit` | выход |

**`:set` обязательна, а не удобна.** Язык не заводит имён (§7.1), поэтому без неё
в оболочке вычислялась бы только арифметика литералов: `user.name` не с чем
сопоставить. Роль хоста играет сама оболочка, и дверь у хоста одна —
`setVariable(ctx, name, text)`.

Отсюда её ограничение: **принимается только литерал**. `:set n = 1 + 1` отказывает
с кодом `Data`, потому что слой данных отвергает выражения. Сообщение об этом
отказе обязано прямо говорить, что данные ставятся литералом, — иначе отказ
читается как ошибка синтаксиса. Ограничение записано как **B30**, и в оболочке
оно заметно раньше, чем где-либо: считать и класть хочется сразу.

## 4. Файлы

| Файл | Ответственность |
|---|---|
| `cli/main.cpp` | цикл, разбор строки, диспетчер команд |
| `cli/printer.hpp` / `.cpp` | печать значения |
| `cli/report.hpp` / `.cpp` | печать диагностики: колонка и стрелка |
| `cli/tests/` | тесты печатника и пересчёта колонки |

Разделение не ради красоты. Печатник и пересчёт колонки — **чистые функции**,
проверяемые тестами; цикл оболочки не проверяется ничем. Оставив их в одном
файле, мы делаем непроверяемым всё.

Внутренние заголовки ядра (`compile.hpp`, `eval.hpp`, `context.hpp`, `data.hpp`,
`diagnostic.hpp`) лежат в `core/src` и наружу не экспортируются. CLI получает их
**приватно**: `target_include_directories(<цель> PRIVATE core/src)` в
`cli/CMakeLists.txt`. Публичная поверхность `core` не меняется — она
по-прежнему `core/include`.

**Почему не через C API.** `core/include/chupascript/chupascript.h` — заглушка с
одной функцией версии; настоящий C API это отдельная работа, идущая после
вычислителя. Оболочке граница на C не нужна. Побочная польза от такого порядка:
когда C API появится, CLI станет его первым настоящим потребителем и покажет,
удобен ли он, — сегодня проверить это нечем.

## 5. Контекст живёт между строками

Один `Context` на сессию: иначе мутации не сохраняются и `script:` бессмыслен.

Отсюда следствие, принимаемое сознательно: **контекст копит мусор**. Освобождения
по одному нет (**B1**), поэтому долгая сессия растит память, а `:reset` —
единственный способ начать чисто, не выходя.

## 6. Печать значения

Литералами языка: `[1, 2, 3]`, `{'a': 1}`, строки в кавычках. Что видишь — то и
можешь набрать.

Кавычки у строк обязательны: типизация строгая, и отличить `1` от `'1'` глазами
— половина отладки выражения.

**Агрегат вправе ссылаться сам на себя.** `obj['self'] = obj` — корректная
программа (§2.3), и наивный печатник на ней зависнет.

Печатник ведёт набор агрегатов, **печатаемых прямо сейчас** — то есть путь от
корня до текущего места, — и снимает агрегат с него, закончив с ним. Агрегат,
встреченный на собственном пути, печатается как `{...}` либо `[...]` вместо
содержимого.

**Именно путь, а не всё виденное за печать.** Хост вправе положить один массив
под двумя именами, и §2.3 объявляет это штатным; такой массив обязан печататься
целиком оба раза, потому что цикла тут нет. Набор всего виденного заменил бы
второе вхождение меткой и соврал бы о данных.

Отслеживается путь, а не глубина: цикл и глубина — разные вещи, а обрывать надо
первое. Предел глубины оборвал бы заодно честное глубокое дерево, каких в данных
с сервера довольно.

**Печатник принадлежит оболочке, а не языку.** `str` агрегаты отвергает (§8.7), и
это правило языка остаётся нетронутым: оболочка печатает для человека, а не
приводит к строке.

## 7. Диагностика

```
> expr: usre.name
        ^
error: unknown name
```

Всё по-английски, включая рамку: оболочка не спорит с ядром, у которого
сообщения английские по правилу проекта.

**Колонка считается по символам UTF-8, а не по байтам.** `Diagnostic::offset` —
смещение в байтах; на кириллице стрелка, поставленная по байту, уедет вправо.
Префикс `expr: ` в счёт колонки входит.

**Печатаются все ошибки прохода, а не первая.** Компиляция отдаёт их массивом
именно для этого. Буфер фиксированного размера; если нашлось больше, чем
поместилось, печатается строка о том, сколько осталось за кадром, — возвращаемое
число это позволяет.

## 8. Ошибки самой оболочки

Отдельных классов не заводится. Отказ команды печатается тем же способом, что и
отказ компиляции, но без стрелки: у команды нет смещения.

| Условие | Ответ |
|---|---|
| Строка без префикса и без `:` | напоминание про `expr:` и `script:` |
| Неизвестная команда | перечисление известных |
| `:set` без имени либо без `=` | форма команды |
| `:set` с недопустимым именем | сообщение слоя данных |
| `:set` с выражением вместо литерала | сообщение слоя данных плюс пояснение про литерал |

## 9. Тесты

Проверяются две чистые функции.

**Печатник:** скаляры каждого вида; пустые массив и объект; вложенность;
самоссылка объекта и самоссылка массива — обе обязаны завершаться; два имени на
один агрегат — печатается дважды полностью, потому что это не цикл; строка с
кавычкой внутри.

**Пересчёт колонки:** ASCII; кириллица до места ошибки; смещение в нулевой
позиции; смещение в конце строки; учёт префикса `expr: ` против `script: `,
которые разной длины.

Цикл оболочки тестами не покрывается: он читает поток и пишет в поток. Это
осознанная граница, и ради неё чистые части и вынесены.

## 10. Что остаётся

- **B30** — постановка данных выражением. Оболочка делает это ограничение
  ощутимым первой.
- **B1** — накопление мусора в контексте; `:reset` его обходит, но не лечит.
- Режим валидации макета: обход JSON-документа поверх той же оболочки.
- Переход на C API, когда он появится.
