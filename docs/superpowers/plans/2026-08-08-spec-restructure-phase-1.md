# Переборка спецификации ChupaLang: фаза 1 (каркас)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Оставить в `docs/spec/` только описание языка и переложить его в новую нумерацию, не меняя содержания, — так, чтобы фаза 2 начиналась с документа, который нигде себе не противоречит.

**Architecture:** Работа механическая и проверяемая. `tools/check-spec.py` из фазы 0 проверяет инварианты спецификации: JSON разбирается, ссылки на файлы разрешаются, таблицы не разъехались, всякий упомянутый идентификатор определён, вырезанное не осталось. Каждая задача сначала добавляет в проверяльщик условие, которое обязано упасть, потом правит документы, потом убеждается, что упавшее поднялось. Задачи, для которых такого условия не бывает, проверяются перечисленными в них грепами.

**Tech Stack:** Markdown, Python 3 (только стандартная библиотека), git. Сборки нет, зависимостей нет.

**Предшествующее состояние.** Фаза 0 завершена, шесть коммитов на ветке `spec/restructure` (`930c68d..09f3df8`). Из языка убраны `++`, `--`, `**`, `&&=`, `||=`, `??=` и завершающие запятые; значение по умолчанию у параметра ограничено литералом. Проверяльщик зелёный.

## Global Constraints

Требования действуют для всякой задачи и в тексте задач не повторяются.

- Ветка `spec/restructure`. На `main` не коммитить.
- Основание решений — `docs/superpowers/specs/2026-08-08-spec-restructure-design.md`, включая раздел 7 «Поправки». При расхождении плана с ним прав документ решения.
- **Спецификация описывает только язык.** Всё о реализации — профили, хост, требования к реализации, механизм воспроизведения на Web — живёт в `docs/impl/` и частью спецификации не является.
- Фаза 1 содержания не меняет. Единственные допустимые изменения смысла — те, что прямо названы в задачах.
- Идентификаторы `CS-*-nnnn` не переиспользуются и не меняются. Вынесенное в `docs/impl/` сохраняет свои идентификаторы там; спецификация их просто не определяет.
- Внутри обратных кавычек — только английский: имена продукций, средств, параметров, ключевых слов. Проза — русская: «получатель», а не «receiver».
- Нормативно тело. Блоки `> Пояснение` и примеры кода ненормативны.
- Регистр — инженера по компиляторам, пишущего для профессионалов. Ни первого лица, ни риторических вопросов, ни интонации списка изменений.
- После каждой задачи `python3 tools/check-spec.py` печатает `нарушений нет` и возвращает 0.
- Проверяльщик читает только `docs/spec/`. `docs/impl/` его инвариантами не проверяется — это осознанно: материал там временный.

Шаблон `раздел[а-я]*` обязателен: русский падёж меняет окончание, и перечисление

творительный падеж, который `раздел 7\|раздела 7\|разделе 7` не находит.
Проверить надо все формы: раздел, раздела, разделу, разделом, разделе.

Каждое совпадение читать в контексте. «Раздел 4» (типы) сохраняет номер и правки не требует; «раздел 1» — тоже. Ссылки на подразделы вида «раздел 4.7» перенумеровывать вместе с разделом.
