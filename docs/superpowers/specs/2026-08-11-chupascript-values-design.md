# ChupaScript: значения и хранилище

Дата: 2026-08-11
Статус: принято

## 1. Область документа

Документ описывает слой, который хранит значения ChupaScript: представление
`Value`, устройство агрегатов, владение памятью и фасад `Context`, через
который к ним обращаются.

Слой не вычисляет и не компилирует. На вход ему ничего не поступает: значения
создаются вызовами, а не разбором. Загрузка JSON, интерпретатор и публичный C
API строятся поверх и описаны отдельно.

Модель значений языка определена в `docs/semantics.md` §2; документ её не
повторяет, а реализует.

## 2. Что решено раньше

Эти решения приняты в `2026-08-10-chupascript-c-api-design.md` и здесь не
пересматриваются:

| Решение | Где |
|---|---|
| Владеющая сущность одна — контекст; всё созданное живёт до его смерти | §3 |
| Поштучного освобождения нет; вся память возвращается разом | §3 |
| `Value` — тег-юнион, без NaN-boxing | §9 |
| Объект — массив пар, отсортированный по ключу, поиск двоичный | §5 |
| Порядок ключей объекта наружу не обещан | §5 |
| Строка — байты, без декодирования UTF-8 | `semantics.md` §2.1 |
| Наружу — непрозрачный хендл с функциями доступа | §9 |

Пересматривается одно: **правило времени жизни хендлов** и **сигнатуры функций
доступа**. Обе правки описаны в §9 и вносятся в спеку C API вместе с этим
документом.

## 3. Хендл — индекс, а не указатель

Всё хранилище адресуется 32-битными индексами в пулы. Указателей внутрь
хранилища значения не содержат.

Причина — не экономия и не вкус. Указатель обязывает хранилище никогда не
переселять данные, а это требование расходится по всей конструкции: арена
превращается в список блоков, наивная реализация на `std::vector` становится
невозможной, а будущая компактификация — недостижимой. Индекс снимает
требование целиком. Данные вправе переезжать; переживает переезд всё, что на
них ссылается.

Прямые следствия:

- **Наивное хранилище — обычные `std::vector`.** Ничего изобретать не нужно.
- **Замена на арену (B1) не трогает ни `Value`, ни интерпретатор.** Меняется
  только то, куда индекс смотрит: в вектор или в смещение внутри одного блока.
  Это подмена приватного поля `Context`, а не переделка слоя.
- **Значение без своего контекста бессмысленно.** Индекс не самоописателен, и
  разрешить его может только тот контекст, который его выдал. Это выражено в
  подписях: всякая функция доступа принимает контекст.

Тот же приём уже применён в `core/src/ast.hpp`: `NodeId` — `std::uint32_t`,
узлы лежат в векторе, дети — диапазоном в боковом пуле. Слой значений повторяет
раскладку слоя разбора, а не заводит вторую.

## 4. `Value`

```cpp
namespace CS {

class Value {
   public:
    enum class Kind : std::uint8_t { Null, Boolean, Number, String, Object, Array };

    static Value null() noexcept;
    static Value boolean(bool v) noexcept;
    static Value number(double v) noexcept;

    Kind kind() const noexcept;

    bool booleanValue() const noexcept;   // предусловие: kind() == Kind::Boolean
    double numberValue() const noexcept;  // предусловие: kind() == Kind::Number

    /// Один ли это агрегат. Для скаляров всегда false.
    bool sameAggregate(Value other) const noexcept;

   private:
    friend class Context;

    Kind kind_;              // смещение 0
    std::uint32_t length_;   // смещение 4 — длина строки в байтах
    union {                  // смещение 8
        bool boolean_;
        double number_;
        std::uint32_t index_;  // String → text_, Array → arrays_, Object → objects_
    };
};

static_assert(sizeof(Value) == 16, "Value должен оставаться в 16 байтах");

}  // namespace CS
```

**Размер — 16 байт, и меньше не выйдет.** Восемь занимает `double`, он же
задаёт выравнивание на восемь; тег добавляет девятый байт, выравнивание
округляет до шестнадцати. Переход на индексы освободил место внутри
объединения, но не сократил структуру. Восьми байт можно достичь единственным
способом — убрав `double` из объединения, то есть NaN-boxing. Это B2.

**Длина строки лежит в самом значении**, а не в заголовке. Поле `length_`
занимает выравнивание после тега и не стоит ни байта. Заголовок стоил бы
дополнительной записи на каждую строку из данных, а их в типичном пейлоаде
тысячи.

**Скалярные аксессоры остались на `Value`,** потому что самодостаточны. Всё,
что требует заглянуть в пул, — методы `Context`. Строка в том числе: индекс без
базы пула байт не разрешается.

**Аксессоры называются `booleanValue()` и `numberValue()`,** а не `boolean()` и
`number()`: короткие имена заняты статическими фабриками `boolean(bool)` и
`number(double)`, и совпадение имён столкнуло бы перегрузки.

**Конструкторы агрегатов приватные, `Context` — единственный друг.** С
указателями внутрь хранилища `friend` был бы лишним: тип заголовка неполон вне
`context.cpp`, и сфабриковать значение-массив было бы попросту не из чего.
Индексы эту защиту снимают — `std::uint32_t` полон везде, и без приватных
конструкторов любой код собрал бы `Value` вида `Array` с произвольным номером
заголовка. Значит закрывать приходится доступом, а не типом.

Заодно `friend` даёт контексту читать `index_`, что нужно ему в каждой
операции. Цена известна: контекст видит всю приватную часть значения, и если
внутри `context.cpp` окажется удобно написать `v.number_` вместо `v.numberValue()`,
компилятор промолчит. Обмен сознательный — без него нет и запрета на фабрикацию
агрегатов.

## 5. Агрегаты и идентичность

Значение указывает на **заголовок**, а не на данные:

```cpp
// context.cpp
struct detail::ArrayRep {
    std::uint32_t start;     // индекс в pool_
    std::uint32_t count;
    std::uint32_t capacity;
};

struct Entry {
    std::uint32_t keyOffset;  // индекс в text_
    std::uint32_t keyLength;
    Value value;
};

struct detail::ObjectRep {
    std::uint32_t start;     // индекс в entries_
    std::uint32_t count;
    std::uint32_t capacity;
};
```

Когда `push` упирается в `capacity`, в хвост `pool_` дописывается диапазон
вдвое больше, элементы копируются, `start` в заголовке правится. **Индекс
заголовка не меняется** — и все значения, ссылающиеся на этот массив,
продолжают видеть один и тот же массив.

Без разделения на заголовок и данные первый же `push` тихо расщепил бы алиас на
две копии. `docs/semantics.md` §2.3 обещает обратное: если хост положил один
массив под двумя путями, изменение через один видно через второй. Разделение
существует ради этого обещания, а не ради памяти.

**Идентичность — это индекс заголовка.** `sameAggregate` сравнивает вид и
индекс. Два пустых массива, созданных по отдельности, различны; копии одного
значения — нет. На этом стоит равенство агрегатов (`semantics.md` §5.4),
которое реализуется этажом выше.

**Цена роста записана честно.** Дорастить массив до `n` элементов через `push`
занимает около `2n` слотов и бросает около `n`. Освобождения нет, мусор копится
до смерти контекста. Это принято сознательно (спека C API §3) и живёт в B1.
Загрузка данных за это не платит: там размер известен заранее, и
`makeArray(capacity)` выделяет ровно нужное.

Три структуры выше в заголовке не появляются — только объявления. Отсюда одно
техническое требование: деструктор `Context` объявляется в `context.hpp` и
определяется в `context.cpp`. Иначе `std::vector` неполного типа
инстанцируется там, где тип ещё неизвестен, и сборка развалится.

Байты нового ключа `objectSet` копирует в `text_`; повторная запись в
существующий ключ ничего не копирует и меняет только значение.

Начальная ёмкость пустого агрегата — ноль; первая запись выделяет четыре
элемента, дальше удвоение. Переполнение `std::uint32_t` при удвоении —
`assert`; настоящий предел на объём недоверенных данных живёт в B5 и приходит с
загрузкой JSON.

**Объект — отсортированный массив пар.** Ключи сравниваются как
`std::string_view`: побайтно, при равенстве префикса короче меньше. Поиск
двоичный, вставка сдвигает хвост. На типичных 3–20 ключах это дешевле любой
хеш-таблицы и не выделяет ничего сверх самого массива. Удаления ключа в языке
нет (`semantics.md` §6.2), поэтому дыр в массиве не бывает.

**Циклы допустимы.** `obj['self'] = obj` записывает копию значения — вид и
индекс. Ни одна операция этого слоя значения рекурсивно не обходит, так что
зациклиться негде.

## 6. Хранилище

```cpp
class Context {
    // ...
   private:
    std::vector<Value> pool_;                  // элементы массивов, диапазонами
    std::vector<detail::ArrayRep> arrays_;
    std::vector<detail::ObjectRep> objects_;
    std::vector<Entry> entries_;               // пары объектов, диапазонами
    std::vector<char> text_;                   // байты строк и ключей
};
```

Пять пулов, каждый растёт дописыванием в хвост. Переезд при росте безвреден:
ссылаются на них индексами.

`text_` хранит байты всех строк — и созданных вызовом, и, в дальнейшем,
скопированного текста данных и исходников. Строковое значение — это пара
«смещение, длина» в нём. Отсюда сохраняется обещание спеки C API о разборе JSON
без лишних копий: строка без escape-последовательностей станет срезом уже
скопированного текста, а не новой записью. Функции, делающей значение из
готового среза `text_`, в этом этапе нет — её заводит загрузчик, единственный,
у кого такой срез появляется.

Дедупликации строк нет: две одинаковые строки занимают место дважды. Для данных
с бэкенда это неважно — повторов там мало; для имён в дереве разбора решение
отдельное и уже записано (B8).

## 7. Фасад `Context`

```cpp
class Context {
   public:
    Context();
    ~Context();
    Context(const Context &) = delete;
    Context &operator=(const Context &) = delete;

    // --- создание ---------------------------------------------------------
    Value makeString(std::string_view bytes);            // копирует в text_
    Value makeArray(std::uint32_t capacity = 0);
    Value makeObject(std::uint32_t capacity = 0);

    // --- чтение -----------------------------------------------------------
    std::string_view string(Value v) const noexcept;     // предусловие: String

    std::uint32_t arrayCount(Value a) const noexcept;    // предусловие: Array
    Value arrayAt(Value a, std::uint32_t index) const noexcept;

    std::uint32_t objectCount(Value o) const noexcept;   // предусловие: Object
    Value objectGet(Value o, std::string_view key) const noexcept;
    bool objectHas(Value o, std::string_view key) const noexcept;
    std::string_view objectKeyAt(Value o, std::uint32_t i) const noexcept;
    Value objectValueAt(Value o, std::uint32_t i) const noexcept;

    // --- изменение --------------------------------------------------------
    bool arraySet(Value a, std::uint32_t index, Value v) noexcept;
    void arrayPush(Value a, Value v);
    bool arrayPop(Value a, Value *out) noexcept;
    void objectSet(Value o, std::string_view key, Value v);

    // --- метрики ----------------------------------------------------------
    std::size_t bytesUsed() const noexcept;
    std::size_t bytesReserved() const noexcept;
};
```

**Чтение за границей возвращает `null`, запись отдаёт признак.** `arrayAt` за
границей и `objectGet` по отсутствующему ключу дают `Value::null()` — это
`semantics.md` §6.1 и §6.2, где обе ситуации объявлены штатными: данные с
сервера неполны. Запись за границу массива по §7.2 ошибка, поэтому `arraySet`
возвращает `bool`. Превратить `false` в диагностику — дело интерпретатора; слой
хранения ни одного сообщения об ошибке не формулирует.

**`objectHas` существует отдельно от `objectGet`** потому, что §6.2 разрешает
записать `null` в ключ, и отличить его от отсутствующего иначе нельзя. Билтин
`has` (§8.3) стоит на этом.

**Значения передаются и возвращаются копией, а не ссылкой.** Шестнадцать байт
копируются дешевле, чем разыменовываются, но причина не в цене. Ссылка на
элемент внутри `pool_` повиснет при первом же росте пула, и `arrayPush(a,
arrayAt(b, 0))` стал бы ошибкой, зависящей от текущей ёмкости. Передача копией
делает этот класс ошибок невыразимым.

**Несовпадение вида — предусловие с `assert`.** `arrayCount` от строки означает,
что интерпретатор не проверил вид перед вызовом, а он обязан был: без проверки
он не выдаст диагностику §6.4. Ловить это в релизной сборке нечем и незачем.

**`bytesUsed` и `bytesReserved` — не украшение.** Ими тесты проверяют историю
про мусор («тысяча `push` оставила столько-то брошенных слотов»), а бенчмарки
меряют цену роста. Без них разговор о том, сколько накоплено за экран, ведётся
на ощупь.

**Фасад разрастётся.** Каждая операция над агрегатом — метод контекста, и со
временем их станет много. Лечится расщеплением на отдельный `Store` внутри
контекста, когда начнёт мешать; сейчас это преждевременно.

## 8. Нехватка памяти

Фатальна. `std::vector` бросает `std::bad_alloc`, до хоста через C-границу
исключение не доедет — на границе будет заглушка, завершающая процесс.

Это решение, а не недосмотр. На телефоне система убивает приложение раньше, чем
аллокатор вернёт отказ, а честная обработка стоила бы признака успеха у каждой
операции над значением и отравила бы весь API ради ветки, которая не
выполняется. Записано в backlog отдельным пунктом.

## 9. Правки в спеку C API

Два места в `2026-08-10-chupascript-c-api-design.md` расходятся с этим
документом и правятся вместе с ним.

**Функции доступа принимают контекст первым параметром.**

```c
ChupaKind chupa_value_kind(const ChupaContext *ctx, const ChupaValue *v);
const char *chupa_value_string(const ChupaContext *ctx, const ChupaValue *v,
                               size_t *len);
```

Иначе строку не достать: по значению известен индекс, база пула байт — нет. То
же для всех `chupa_array_*` и `chupa_object_*`.

Это не потеря, а устранение противоречия: §6 той же спеки уже требует, чтобы
контекст принимали все функции без исключения, а перечисленные сигнатуры
`chupa_value_*` его не принимали. Заодно подпись перестаёт врать о времени
жизни: значение без своего контекста бессмысленно, и теперь это выражено типом.
В Swift-обёртке отсюда получается `ctx.string(of: v)`, где контекст удерживается
тем же объектом, через который к значению обращаются.

**Правило времени жизни становится точным.** Из §3 уходит оговорка «правило
строже реальности — хендл в граф данных живёт до смерти контекста». При
переезжающих пулах она перестаёт быть верной: указатель, выданный до роста,
повисает. Обещание «действительны до следующего вычисления на этом контексте»
остаётся в силе и теперь описывает реальность буквально.

Хост, нарушавший правило и не замечавший этого, начнёт падать. Считаем это
приобретением: нарушение перестаёт быть безнаказанным, а ASan ловит его в
тестах, а не через полгода на устройстве.

## 10. Тесты

Помимо очевидных проверок создания и чтения, набор обязан закрыть три вещи,
ради которых дизайн именно такой.

**Алиас переживает рост.** Два значения на один массив; `push` за пределы
текущей ёмкости; оба видят новую длину и новый элемент. Главный тест этапа: без
него разделение заголовка и данных выглядит перестраховкой.

**Идентичность.** Два пустых массива различны; копия значения — тот же массив;
`sameAggregate` на скалярах даёт `false`.

**Цикл.** `obj['self'] = obj` строится, читается и не зацикливается.

Дальше — по операциям:

- массив: чтение за границей даёт `null`, запись за границу даёт `false`,
  `pop` на пустом даёт `false`, `pop` возвращает последний;
- объект: вставка сохраняет порядок сортировки, повторный ключ заменяет
  значение, `null` в ключе отличим от отсутствия через `objectHas`, ключ с
  не-ASCII байтами находится, перечисление отдаёт все ключи;
- строки: пустая строка, строка с нулевым байтом внутри, длина считается в
  байтах;
- размер и копируемость: тест проверяет `sizeof(Value) == 16` и
  `std::is_trivially_copyable_v<Value>` рядом с одноимёнными `static_assert` —
  свойство от вида значения не зависит, дублировать его на все шесть видов
  незачем.

## 11. Бенчмарки

Записываются в `benchmarks/baseline.json` тем же механизмом, что и парсер, и
служат базой для решения по B1.

- `push` тысячи элементов — цена роста и копирования;
- поиск ключа при 3, 8 и 20 ключах — проверка утверждения «двоичный поиск
  дешевле хеш-таблицы на таких размерах»;
- вставка нового ключа в объект тех же размеров — цена сдвига хвоста;
- обход массива из тысячи значений — цена разыменования через индекс.

## 13. Что остаётся отложенным

- **B1** — замена пулов ареной. После этого документа это подмена приватных
  полей `Context`: ни `Value`, ни интерпретатор, ни тесты не меняются. Признак,
  что пора, — накопление мусора или стоимость аллокаций видны в бенчмарках.
- **B2** — восемь байт вместо шестнадцати через NaN-boxing. Единственный путь;
  тег-юнион с `double` внутри меньше шестнадцати не бывает.
- **B5** — пределы на объём недоверенных данных. Приходит с загрузкой JSON.
- **B14** — глава 10 `docs/semantics.md`. Требует B3, то есть формы `set_data`,
  которая решается вместе с C API. В этот этап не входит.
