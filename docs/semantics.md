# Семантика ChupaScript

**Версия:** 0.1
**Дата:** 2026-08-10
**Статус:** нормативный документ; глава 10 — заглушка

Этот документ — **единственный источник правды о семантике ChupaScript**. При
расхождении с любым другим текстом, комментарием в коде или реализацией
правильным считается этот документ.

Синтаксис определён в `docs/grammar.md`. История принятия решений и их
обоснования — в `docs/superpowers/specs/2026-08-10-chupascript-semantics-design.md`.

---

## 1. Область применения

Документ определяет: модель значений, вычисление выражений и стейтментов,
приведение типов, поведение всех операторов и встроенных функций, классификацию
ошибок.

Документ **не** определяет: способ доставки исходного текста в рантайм,
внутреннее представление значений в памяти, стратегию управления памятью. Всё
это следует из главы 10, которая пока не написана.

## 2. Модель значений

### 2.1 Типы

Шесть типов, закрытый список:

| Тип | Содержимое |
|---|---|
| `Null` | единственное значение `null` |
| `Boolean` | `true` или `false` |
| `Number` | IEEE 754 binary64 |
| `String` | последовательность байт |
| `Object` | отображение `String` → значение |
| `Array` | последовательность значений, индексация с нуля |

`Number` включает все значения IEEE 754, в том числе `NaN`, `+Infinity`,
`-Infinity` и отрицательный ноль. Отдельного целочисленного типа нет.

`String` — последовательность **байт**, а не символов. Рантайм не декодирует
UTF-8, не проверяет его корректность и не нормализует.

Порядок ключей в `Object` **не определён** и может различаться между версиями
рантайма.

### 2.2 Void

`Void` — пометка компилятора, означающая «функция не возвращает значения».
Значением языка `Void` не является: сохранить его некуда, тип этот недостижим
для программы. Использование результата `Void`-функции — ошибка
компиляции (§9.1).

### 2.3 Ссылочность

`Object` и `Array` — **ссылочные**. Присваивание, передача аргументом и запись в
поле копии не создают. Если хост положил один и тот же массив в контекст под
двумя путями, изменение через один виден через второй:

```
push(state.items, 3);
count(state.cart.items)     // тоже увеличился, если это один массив
```

Создать второе имя для агрегата средствами языка нельзя: имён язык не заводит.
Алиасы возникают только там, где их создал хост.

`Null`, `Boolean`, `Number`, `String` — значения. Мутировать их нечем: операций,
изменяющих строку на месте, в языке нет.

Литерал `Object` или `Array` создаёт **новый** объект при каждом вычислении.

Ссылочность допускает циклы: `obj['self'] = obj;` — корректная программа. Ни
одна операция языка на цикле не зацикливается, поскольку рекурсивного обхода
значений нет ни в одной из них: равенство сравнивает агрегаты по идентичности
(§5.4), приведение агрегата к строке запрещено (§4.2).

Цикл, однако, **не освобождается**. Память движка держится счётчиком ссылок, а
счётчик цикл не соберёт никогда: две коробки, ссылающиеся друг на друга,
удерживают друг друга сами. `obj['self'] = obj` и `push(obj.items, obj)` —
корректные программы, но каждая из них оставляет свои коробки жить до конца
процесса, даже после разрушения контекста.

Сборщика циклов в движке нет и не планируется: это отдельная подсистема,
стоящая больше всего остального движка, а данные, ради которых движок писался,
приходят с бэкенда деревом. Отладочный прогон под детектором утечек
(`tools/asan.sh`) на таком цикле краснеет — случайный цикл виден, а не молчит.

## 3. Вычисление

### 3.1 Два режима

| Режим | Стартовый символ | Результат |
|---|---|---|
| `evalExpression` | `Expression` | значение либо ошибка |
| `runScript` | `Script` | только признак успеха либо ошибка |

Скрипт значения не возвращает: `return` в языке отсутствует. Единственный его
результат — побочные эффекты, произведённые над данными, полученными из
контекста.

### 3.2 Выражения не имеют побочных эффектов

**Ни одно выражение не может изменить данные.** Для билтинов это следует из
двух правил, а не из отдельной проверки:

- билтин, изменяющий данные, не возвращает значения (§8);
- использование результата `Void`-функции — ошибка компиляции (§2.2), поэтому
  такой вызов не может быть ни операндом, ни аргументом.

Для функций хоста этот вывод неверен: хост вправе объявить функцию, которая и
меняет состояние, и возвращает значение (`CHUPA_FN_RETURNS_VALUE` без
`CHUPA_FN_PURE` — законное сочетание, §10.1). Третье правило действует ровно
для них: вызов функции, не объявленной чистой, в дереве режима `Expression` —
ошибка компиляции (`docs/grammar.md` §6.3). У билтинов чистота держится по
устройству, у функций хоста — по объявлению плюс эта проверка; вместе все три
правила и дают то же самое свойство: ни один вызов в выражении не меняет
данные.

Свойство действует в обоих режимах. В режиме `evalExpression` оно к тому же
единственно возможное: стейтментов там нет, а значит нет ни присваиваний, ни
`CallStatement`.

Следствие: вычисление выражения не наблюдаемо снаружи. Уточнение, кем именно:
состояние движка функция хоста через C API изменить не может — контекст на
время её вызова закрыт для записи (§10.1); эффект за пределами движка
невозможен потому, что
грязную функцию в дерево выражения не пускает третье правило выше. Право
хоста кэшировать результат, вычислять его лениво, вне порядка обхода дерева
вьюх или не вычислять вовсе держится теперь на обоих основаниях сразу.

### 3.3 Порядок вычисления

Слева направо, **зафиксирован**. Аргументы вызова и операнды бинарных операторов
вычисляются в порядке записи.

Исключения — операторы с коротким замыканием (§5.5, §5.6, §5.7): у них правый
операнд либо ветвь могут не вычисляться вовсе.

> **Почему порядок зафиксирован.** На значение он не влияет: побочных эффектов в
> выражениях нет (§3.2). Но он влияет на **диагностику**: если ошибочны оба
> операнда, как в `user.age + item.price`, порядок определяет, о какой из двух
> ошибок будет сообщено. Незафиксированный порядок дал бы разные сообщения на
> разных сборках рантайма для одного и того же макета.

### 3.4 Ошибки времени выполнения

Ошибка **прерывает вычисление немедленно**. Поглощения ошибок нет ни в одном
операторе.

- `evalExpression` возвращает хосту признак ошибки. Значения нет.
- `runScript` прекращает исполнение в точке ошибки. Изменения, произведённые
  предшествующими стейтментами, **сохраняются**; откат не выполняется.
- `??` перехватывает только `null` и ошибку не гасит (§5.6).
- `&&` и `||` ошибку не гасят: `ошибка && false` — ошибка.

Полный перечень ошибок — глава 9.

## 4. Приведение типов

В языке существует **единственное** приведение, и оно одностороннее:

> В позиции, где требуется `String`, значение скалярного типа (`Null`,
> `Boolean`, `Number`, `String`) приводится к строке. Обратного приведения — из
> строки в любой другой тип — не существует нигде. `Object` и `Array` не
> приводятся никуда.

### 4.1 Позиции, требующие String

Список закрытый:

- ключ объекта: `obj[k]`, а также аргумент-ключ у `has`
- аргументы `format` начиная со второго
- аргумент `str`

Во всех прочих позициях несовпадение типов — ошибка:

```
1 + '1'        // ошибка: арифметика требует Number
1 == '1'       // ошибка: сравнение разных типов
1 < '2'        // ошибка
'a' && true    // ошибка: логика требует Boolean
arr['0']       // ошибка: индекс массива требует Number
```

Для явного приведения предназначен `str` (§8.7).

### 4.2 Правила приведения к String

| Тип | Результат |
|---|---|
| `String` | сама строка |
| `Boolean` | `'true'` либо `'false'` |
| `Null` | `'null'` |
| `Number` | см. §4.3 |
| `Object`, `Array` | ошибка |

### 4.3 Number → String

Кратчайшее десятичное представление, которое читается обратно в то же самое
значение double. Правила применяются в порядке перечисления:

1. `NaN` даёт `'nan'`, бесконечности — `'inf'` и `'-inf'`.
2. Ноль даёт `'0'` либо `'-0'` по знаку.
3. При `1e-7 ≤ |x| < 1e21` запись фиксированная.
4. Вне этого диапазона — научная, с показателем минимальной длины: `1e-8` даёт
   `'1e-8'`, `1e21` даёт `'1e+21'`.

Порог отделяет числа, которые человек читает как числа, от тех, где научная
запись короче и понятнее. Он же объясняет, почему `1000000` остаётся
`'1000000'`, а `1e21` становится `'1e+21'`.

```
1            → '1'
1.5          → '1.5'
1000000      → '1000000'
0.1 + 0.2    → '0.30000000000000004'
1e21         → '1e+21'
```

Особые значения:

| Значение | Результат |
|---|---|
| `+Infinity` | `'inf'` |
| `-Infinity` | `'-inf'` |
| `NaN` | `'nan'` |
| отрицательный ноль | `'-0'` |

Следствия, которые обязана учитывать реализация:

- `-0 == 0` истинно, но `obj[-0]` и `obj[0]` — **разные ключи** (`'-0'` и `'0'`).
- `obj[null]` и `obj['null']` — один ключ. То же для `true`, `1` и прочих
  скаляров.
- `obj[0.1 + 0.2]` даёт ключ `'0.30000000000000004'`, который невозможно набрать
  вручную.

## 5. Операторы

Приоритет и ассоциативность определены в `docs/grammar.md` §5.4. Здесь — только
семантика.

### 5.1 Унарные

| Оператор | Операнд | Результат |
|---|---|---|
| `!` | `Boolean` | отрицание |
| `-` | `Number` | смена знака |

Любой другой тип операнда — ошибка. `-` над `NaN` даёт `NaN`, над нулём —
отрицательный ноль.

### 5.2 Арифметические

`+` `-` `*` `/` `%` принимают **только Number**, оба операнда. Любой другой тип
— ошибка.

Вычисление выполняется по IEEE 754 без дополнительных проверок:

```
1 / 0        // +Infinity
-1 / 0       // -Infinity
0 / 0        // NaN
```

`%` берёт **знак делимого** — поведение `std::fmod`:

```
7 % 3        //  1
-5 % 3       // -2
5 % -3       //  2
5.5 % 2      //  1.5
5 % 0        //  NaN
```

Конкатенации строк через `+` нет. Строки собираются `format` (§8.8).

### 5.3 Сравнения порядка

`<` `>` `<=` `>=` принимают **только Number**. Строки, булевы значения и
агрегаты сравнивать нельзя — ошибка.

Если хотя бы один операнд `NaN`, все четыре оператора дают `false`.

> **Почему строки не сравниваются.** Побайтовый порядок не соответствует
> алфавитному: `'Я' < 'а'` было бы истинно, поскольку заглавные кириллические
> буквы лежат в юникоде раньше строчных. Правильный порядок требует collation по
> UAX #10 и таблиц ICU.

### 5.4 Равенство

`==` и `!=`. Правила применяются в порядке перечисления:

1. Если один из операндов `null` — результат истинен тогда и только тогда, когда
   второй операнд тоже `null`.
2. Если типы операндов различаются — **ошибка**.
3. `Number` сравниваются по IEEE 754. `NaN` не равен ничему, включая себя:
   `x == x` ложно, если `x` есть `NaN`.
4. `String` сравниваются побайтово. Нормализация юникода не выполняется.
5. `Boolean` сравниваются по значению.
6. `Object` и `Array` сравниваются **по идентичности**: равны тогда и только
   тогда, когда это один и тот же объект.

```
// state.a и state.b — один и тот же массив
state.a == state.b     // true
state.a == [1, 2]      // false — литерал создаёт новый массив
1 == '1'               // ошибка
null == 0              // false
null == null           // true
```

`!=` во всём эквивалентен отрицанию `==`, включая случай ошибки.

> **Почему по идентичности.** Структурное сравнение имеет неограниченную
> стоимость в горячем пути и требует защиты от циклов: `obj['self'] = obj;`
> уронил бы наивную рекурсию переполнением стека, которое в C++ не
> перехватывается. Глубокое сравнение при необходимости добавляется отдельным
> билтином.

### 5.5 Логические

`&&` и `||` принимают **только Boolean** и возвращают `Boolean`. Любой другой
тип операнда — ошибка. Truthiness в языке отсутствует.

Оба **замыкаются коротко**: правый операнд не вычисляется, если левый определил
результат.

```
false && X      // false, X не вычисляется
true  || X      // true,  X не вычисляется
```

Это позволяет защищать правую часть проверкой слева:

```
count(arr) > 0 && arr[0] == 1
```

Ошибка в левом операнде прерывает вычисление и не поглощается правым:
`ошибка && false` — ошибка.

### 5.6 Оператор `??`

`a ?? b` даёт `a`, если `a` не есть `null`, иначе `b`. Правый операнд
вычисляется только при `null` слева. Правоассоциативен: `a ?? b ?? c` есть
`a ?? (b ?? c)`.

Типы операндов произвольны и совпадать не обязаны.

`??` перехватывает **только `null`**. Ошибку он не гасит:

```
user.name ?? 'Гость'        // 'Гость', если name есть null
(user.age + 1) ?? 0         // ошибка, если age не Number
```

### 5.7 Тернарный оператор

`c ? a : b`. Условие `c` обязано быть `Boolean`, иначе ошибка. Ветви могут иметь
любые типы, совпадать они не обязаны. Вычисляется **только выбранная** ветвь.

## 6. Доступ к данным

### 6.1 Индексация массива

`arr[i]`, где `arr` есть `Array`.

Индекс `i` обязан быть `Number`, целым и не меньше нуля. Дробный индекс,
отрицательный индекс и индекс любого другого типа — ошибка. Приведения к
`Number` в языке нет, поэтому `arr['0']` не работает.

| Операция | Индекс в границах | Индекс за границей |
|---|---|---|
| Чтение | элемент | `null` |
| Запись | заменяет элемент | **ошибка** |

Массив расширяется только через `push`.

> **Почему чтение и запись несимметричны.** Чтение за границей — штатная
> ситуация: данные с сервера неполны. Запись за границу — ошибка логики автора:
> она означает намерение создать элемент, для чего существует `push`.

### 6.2 Доступ по ключу

`obj[k]` и `obj.k`, где `obj` есть `Object`.

В форме `obj[k]` ключ приводится к строке по §4. В форме `obj.k` ключом является
имя `k` буквально, как строка.

| Операция | Ключ существует | Ключа нет |
|---|---|---|
| Чтение | значение | `null` |
| Запись | заменяет значение | создаёт ключ |

Удаления ключа в языке нет. Запись `null` создаёт ключ со значением `null`;
отличить его от отсутствующего можно только через `has` (§8.3).

Форма `obj.k` требует, чтобы `k` был идентификатором: ключи, совпадающие с
зарезервированными словами или содержащие не-ASCII, доступны только через
`obj['ключ']`.

### 6.3 Чтение у `null`

**Чтение чего угодно у `null` даёт `null`** — и по ключу, и по индексу:

```
null.foo        // null
null['foo']     // null
null[0]         // null
```

Правило продолжает §6.1 и §6.2: отсутствующее значение читается как `null`, и
чтение через него — тоже. Поэтому путь любой глубины безопасен, а запасное
значение ставится один раз в конце:

```
user.profile.avatar ?? 'placeholder.png'
```

Отдельного оператора безопасного доступа в языке нет: он был бы неотличим от
обычного.

Следствие, которое надо принимать во внимание: **опечатка в пути не
диагностируется.** `user.prfoile.avatar` даёт `null`, а не ошибку.

### 6.4 Чтение у значения неподходящего типа

Индексация определена для `Array`, доступ по ключу — для `Object`, чтение у
`null` — правилом §6.3. Прочие типы — ошибка:

```
(5).foo         // ошибка
'abc'[0]        // ошибка
true['k']       // ошибка
```

## 7. Имена и присваивание

### 7.1 Имена

Объявлений в языке нет. Всякий идентификатор в программе — **чтение из
контекста**, предоставленного хостом.

```
user.name                 // 'user' — глобальная переменная контекста
state.items[0]
```

Контекст неизменен по составу: программа не может добавить в него имя или
удалить существующее. Изменять она может только содержимое агрегатов, лежащих в
контексте (§7.2).

### 7.2 Присваивание

Цель присваивания — путь внутри контекста:

```
state.count = 1;
state.items[0] = product;
user.profile.name = 'Вася';
```

**Целью не может быть само имя.** `state = {...};` разбирается грамматикой, но
отвергается ошибкой компиляции — той же природы, что и статические проверки
`docs/grammar.md` §6: имя ставит хост, программа же меняет только содержимое
агрегатов, лежащих в контексте (§7.1).

Причина не в стилистике. Замена значения имени целиком выбросила бы агрегат, на
который могли остаться ссылки из других имён, а §2.3 обещает, что изменение
через одно имя видно через второе. После `state = {}` алиас продолжил бы
указывать на прежний массив, и данные разъехались бы тихо.

Все подвыражения цели вычисляются до вычисления правой части. Требования к
целям-индексам и целям-ключам — те же, что при чтении (§6.1, §6.2), с двумя
отличиями:

- запись за границу массива — ошибка;
- запись в `null` — **ошибка**. Мягкость §6.3 распространяется только на чтение:
  `user.profile.name = 'Вася'` при `profile` равном `null` записывать некуда.

**Вычисление** цели идёт первым, **проверка** — нет: годность базы (объект она
или нет) и годность индекса проверяются уже после вычисления правой части.
Если неисправны обе стороны, диагностика указывает на правую часть:

```
items[-1] += 1 + 'a';           // Type, не Range — RHS отказывает раньше проверки индекса
user.profile.name = items[-1];  // Range, не Type — при profile == null; RHS отказывает раньше проверки базы
```

Правило одинаково для всех форм цели и относится и к составному
присваиванию: эквивалентность §7.3 говорит о результате, а не о порядке
проверок, и при неисправности обеих сторон побеждает та же правая часть.

### 7.3 Составное присваивание

`x += e` эквивалентно `x = x + e` с одним уточнением: подвыражения цели
вычисляются **ровно один раз**.

```
state.items[count(state.log) - 1] += 1;
```

вычисляет индекс однократно и использует результат и для чтения, и для записи.
Аналогично для `-=`, `*=`, `/=`.

## 8. Встроенные функции

Двенадцать функций. Аргумент неподходящего типа — ошибка выполнения. Неверное
число аргументов — ошибка компиляции.

**Команды отделены от запросов.** Билтин либо изменяет данные и возвращает
`Void`, либо возвращает значение и ничего не изменяет. Третьего не бывает.
Поэтому «мутирует ли билтин» читается прямо из типа возврата, отдельной пометки
не требуется, а выражения оказываются свободны от побочных эффектов (§3.2).

Колонка «детерминирован» предназначена для кэширования на стороне хоста; сейчас
все билтины детерминированы, колонка существует для будущих — например, функции
текущего времени.

| Функция | Сигнатура | Детерминирован |
|---|---|---|
| `count(x)` | `Array \| Object \| String` → `Number` | да |
| `keys(obj)` | `Object` → `Array` | да |
| `has(obj, k)` | `Object`, скаляр → `Boolean` | да |
| `last(arr)` | `Array` → значение | да |
| `push(arr, v)` | `Array`, значение → `Void` | да |
| `pop(arr)` | `Array` → `Void` | да |
| `str(x)` | скаляр → `String` | да |
| `format(fmt, …)` | `String`, … → `String` | да |
| `min(a, b)` | `Number`, `Number` → `Number` | да |
| `max(a, b)` | `Number`, `Number` → `Number` | да |
| `abs(x)` | `Number` → `Number` | да |
| `round(x)` | `Number` → `Number` | да |

### 8.1 count

`Array` — число элементов. `Object` — число ключей. `String` — число **байт**,
не символов: `count('привет')` даёт `12`, `count('😀')` даёт `4`.

### 8.2 keys

Возвращает массив ключей объекта. **Порядок не определён** и может различаться
между версиями рантайма. Макет, полагающийся на порядок, непереносим.

### 8.3 has

Истинно, если ключ присутствует в объекте, независимо от его значения. Ключ
приводится к строке по §4. Единственный способ отличить отсутствующий ключ от
ключа со значением `null`.

### 8.4 last

Возвращает последний элемент массива. На пустом массиве — `null`.

Выразить через индексацию нельзя: `arr[count(arr) - 1]` на пустом массиве даёт
`arr[-1]`, а отрицательный индекс — ошибка (§6.1).

### 8.5 push

Добавляет значение в конец массива. Значения не возвращает; использование
результата — ошибка компиляции.

### 8.6 pop

Удаляет последний элемент. **Значения не возвращает.** На пустом массиве не
делает ничего.

Чтобы использовать удаляемый элемент, его читают отдельным шагом:

```
state.taken = last(state.items);
pop(state.items);
```

> **Про имя.** В большинстве языков `pop` означает «снять и вернуть». Здесь имя
> сохранено ради парности с `push`, но возврата у него нет: команды и запросы в
> языке разделены (§8). Прецедент — `std::stack` в C++, где `pop()` тоже `void`,
> а значение читается через `top()`.

### 8.7 str

Приводит скаляр к строке по правилам §4.2 и §4.3. `Object` и `Array` — ошибка.

### 8.8 format

Собирает строку по шаблону. Плейсхолдер — `${}`, аргументы подставляются слева
направо. Последовательность `$${}` даёт литеральное `${}`.

```
format('Привет, ${}!', user.name)
format('${} из ${}', cart.taken, cart.total)
format('цена $${}', item.price)          // 'цена ${}'
```

Аргументы приводятся к строке по §4; агрегат в аргументе — ошибка.

Число плейсхолдеров обязано совпадать с числом аргументов. Если шаблон является
строковым литералом, несовпадение — ошибка компиляции; иначе — ошибка
выполнения.

### 8.9 min, max

Ровно два аргумента. Для трёх и более применяется вложение: `min(a, min(b, c))`.

`NaN` в любом из аргументов даёт `NaN` независимо от позиции — то же правило,
что у арифметики (§5.2). Это расходится с `fmin`/`fmax` из стандартной
библиотеки C, которые `NaN` игнорируют и возвращают второй операнд.

### 8.10 abs, round

`abs` — модуль. `round` округляет **от нуля** (`std::round`):

```
round(0.5)     //  1
round(1.5)     //  2
round(2.5)     //  3
round(-0.5)    // -1
```

Результат — `Number` с нулевой дробной частью, отдельного целого типа нет.

## 9. Ошибки

Ошибки разделены по стадии, на которой обнаруживаются. Ошибка компиляции
означает, что макет не применяется целиком: пришедший с сервера макет отвергнут,
хост остаётся на прежнем. Ошибка выполнения прерывает вычисление посреди работы,
и сделанное к этому моменту остаётся сделанным.

Отсюда правило, по которому условие попадает в ту или иную таблицу: **всё, что
устанавливается по одному дереву и составу имён, устанавливается до исполнения.**

Диагностирующих составных частей конвейера четыре: лексер и парсер строят
дерево, статический проход проверяет его до исполнения, вычислитель исполняет
уже проверенное. Колонка «Кто» называет эту часть, колонка «Код» — класс
ошибки из `core/src/diagnostic.hpp`.

### 9.1 Ошибки компиляции

Программа не компилируется, макет не применяется.

| Условие | Код | Кто |
|---|---|---|
| Лексические (`docs/grammar.md` §4.9) | `Syntax` | лексер |
| Синтаксические (`docs/grammar.md` §5.5) | `Syntax` | парсер |
| Вызов неизвестной функции | `Name` | проход |
| Неверное число аргументов билтина | `Name` | проход |
| Вызов билтина, возвращающего значение, в позиции стейтмента | `Name` | проход |
| Использование результата `Void`-билтина | `Name` | проход |
| Несовпадение числа плейсхолдеров `format` при литеральном шаблоне | `Name` | проход |
| Цель присваивания — само имя | `Name` | проход |
| Обращение к необъявленному имени | `Name` | проход |

Последняя строка верна при условии, зафиксированном в §10: состав имён известен
целиком к моменту компиляции, и вычисление идёт по тому же `Context`, по
которому прошёл `check`. `compileExpression` (`core/src/compile.cpp`) и
`evalExpression` (`core/src/eval.cpp`) принимают `Context` двумя независимыми
параметрами, и ничто не заставляет их совпадать — расхождение остаётся
открытым пунктом (`B23`, `docs/backlog.md`). Если оно случилось, диагностика
сдвигается в вычислитель и меняет сообщение: `"unknown name"` у прохода на
`"unknown global"` у вычислителя — см. последнюю строку §9.2.

### 9.2 Ошибки выполнения

Прерывают вычисление (§3.4).

| Условие | Код | Кто | Пример |
|---|---|---|---|
| Операнд `!` не `Boolean` | `Type` | вычислитель | `!1` |
| Операнд унарного `-` не `Number` | `Type` | вычислитель | `-'a'` |
| Операнд арифметики не `Number` | `Type` | вычислитель | `1 + 'a'` |
| Операнд сравнения порядка не `Number` | `Type` | вычислитель | `'a' < 'b'` |
| Операнды `==` разных типов, ни один не `null` | `Type` | вычислитель | `1 == '1'` |
| Операнд логической операции не `Boolean` | `Type` | вычислитель | `1 && true` |
| Условие тернарного оператора не `Boolean` | `Type` | вычислитель | `1 ? a : b` |
| Индекс массива не `Number` | `Type` | вычислитель | `items['0']` |
| Индекс массива дробный, отрицательный, бесконечный или `NaN` | `Range` | вычислитель | `items[-1]`, `items[1.5]`, `items[1 / 0]`, `items[0 / 0]` |
| Запись за границу массива | `Range` | вычислитель | `items[100] = 1` |
| Индексация значения, не являющегося `Array`, `Object` и не `null` | `Type` | вычислитель | `true[0]`, `(5)[0]`, `'abc'[0]` |
| Доступ по ключу у значения, не являющегося `Object` и не `null` | `Type` | вычислитель | `(5).foo` |
| Запись по ключу в значение, не являющееся `Object` | `Type` | вычислитель | `(5).foo = 1`, `user.profile.name = 'Вася'` при `profile == null` |
| Запись по индексу в значение, не являющееся `Array` либо `Object` | `Type` | вычислитель | `(5)[0] = 1` |
| Приведение агрегата к строке | `Type` | вычислитель | `str([1])`, `obj[[1]]` |
| Аргумент билтина неподходящего типа | `Type` | вычислитель | `count(1)` |
| Несовпадение числа плейсхолдеров `format` при нелитеральном шаблоне | `Type` | вычислитель | |
| Обращение к имени, отсутствующему в `Context` на момент вычисления | `Name` | вычислитель | `foo.x`, если `compileExpression` видел глобальную переменную `foo`, а `evalExpression` — нет |

Деления на ноль в списке нет: оно даёт значение IEEE, а не ошибку (§5.2).
Последняя строка достижима только при рассинхроне `Context` между компиляцией и
вычислением (§9.1, `B23`); при обычном порядке работы имя проверяет проход, и
до этой строки дело не доходит.

## 10. Граница с хостом

**Глава написана частично: раздел о функциях хоста готов, раздел о данных —
ещё нет.**

### 10.1 Функции хоста

Хост-функция — имя, зарегистрированное хостом на конкретном `Context` через
`chupa_register` и с этого момента доступное программе наравне со встроенными
функциями (§8): макет, вызывающий `formatDate(item.ts)`, не различает, кто из
двух это реализовал. Пространство имён общее, столкновение отклоняется при
регистрации.

**Наружу только скаляр, внутрь — любое значение.** Аргументы, которые
хост-функция получает от вычислителя, — значения языка без ограничения на тип,
включая `Array` и `Object`; они действительны только на время вызова, дольше
хост-функция удерживает то, что явно удержала. Результат, который хост-функция
возвращает вычислителю, ограничен скаляром: `Null`, `Boolean`, `Number`,
`String`. Возврат агрегата из хост-функции не реализован (`docs/backlog.md`).

**Смысл `pure` и `deterministic`.** Оба флага определяются не через
состояние, которое хост-функция меняет, — контекст на время вызова закрыт
(`chupascript.h`, докблок `ChupaHostFunction`), и состояние движка хост-функция
через C API изменить не может, — а через то, что флаг **разрешает** сделать с
вызовом:

| Флаг | Что разрешает | Кто наблюдатель |
|---|---|---|
| `CHUPA_FN_PURE` | пропустить вызов, повторить его, переставить с другим — и никто снаружи не заметит | продукт: аналитика, навигация, показанный алерт |
| `CHUPA_FN_DETERMINISTIC` | не звать функцию повторно, а взять прошлый ответ из кэша | программа: значение выражения |

Ни один флаг не поглощает другой: чистота бережёт право хоста не вычислять
props — положить вызов с побочным эффектом в пропс значит потерять эффект при
кэшировании, ленивом вычислении или пропуске невидимой вьюхи, без единой
ошибки, — а детерминированность бережёт верность самого значения. Сочетание
«недетерминированная и без побочных эффектов» встречается: `now()`,
`screenWidth()` можно звать в props, но пересчитывать каждый кадр. Сочетание
«грязная и детерминированная» отвергается при регистрации: детерминированность
обещает, что результат можно не пересчитывать, а грязная функция зовётся ради
эффекта, который пропуск вызова отменяет.

Оговорка «через C API» существенна: хост, зарегистрировавший функцию прямо
через `CS::Context::registerFunction` и положивший `CS::Context *` себе в
`user_data`, до методов контекста дотянется. Те из них, чья сигнатура
позволяет отказать, отказывают и в релизе; `setGlobal` и `setGlobalString`
возвращают `void` и ловятся только утверждением отладочной сборки
(`docs/backlog.md` B34).

Ещё одно, чего движок не отвергает: разрушение скомпилированной единицы
изнутри колбэка. Ни `chupa_expression_destroy`, ни `chupa_script_destroy` не
получают контекста и потому не могут спросить, идёт ли вычисление; не
разрушать единицу, пока колбэк не вернулся, — обязательство хоста
(`docs/backlog.md` B67).

**Побочный эффект хост-функции попадает в язык единственным путём — через
другую хост-функцию, читающую изменённое состояние хоста.** Отсюда
обязательство хоста, которое ядро проверить не может, — как и UTF-8 из
`chupascript.h`: **функция, читающая изменяемое состояние хоста, обязана быть
объявлена недетерминированной.** Хост, объявивший `readCounter()`
детерминированной «в пределах кадра», нарушает это обязательство, и кэш
props отдаст протухшее значение без единой ошибки движка.

**Грязная функция хоста доступна только скрипту.** В дереве режима
`Expression` вызов функции, не объявленной чистой, — ошибка компиляции
(`docs/grammar.md` §6.3); в режиме `Script` он доступен как стейтмент,
наравне с грязным билтином.

**Порядок: регистрация → компиляция → вычисление.** `chupa_register` обязан
быть вызван до первой компиляции на данном `Context` — после неё регистрация
отказывает (`docs/superpowers/specs/2026-08-20-host-functions-design.md` §5.1,
§8.1). Условие того же рода, что у глобальных переменных (`B23`,
`docs/backlog.md`): состав
имён, которые проверяет статический проход, обязан быть известен целиком к
моменту компиляции, и для имён функций эта гарантия уже обеспечена признаком
«на этом `Context` уже компилировали» — для корневых имён (глобальных
переменных) она остаётся открытой (`B23`, `docs/backlog.md`).

### 10.2 Данные

Здесь будут определены: как хост наполняет контекст и какие имена в нём видны
программе; что происходит со значением, отданным хостом в программу и обратно;
переживают ли значения вызов.

Вопросы связаны и определяют модель управления памятью целиком. Если значения не
покидают вычисление, достаточно арены со сбросом после каждого вызова — ни
сборщика мусора, ни подсчёта ссылок не потребуется. Если значения переживают
вызов, необходимо решить, сохраняется ли идентичность объекта между кадрами: от
этого зависит, наблюдаема ли мутация через сохранённую ссылку.

Три частных вопроса, относящихся сюда же:

- Обращение к имени, отсутствующему в контексте, — ошибка компиляции (§9.1),
  а не ошибка выполнения. Верно это при одном условии: состав имён известен на
  момент компиляции целиком, прежде чем проход (§9.1) сможет его сверить. Условие
  — свойство, которое обязана сохранять всякая будущая возможность языка, а не
  запрет на динамические имена сам по себе: расширение, вводящее имя, состав
  которого не фиксирован до компиляции, лишает проверку имён почвы.
- Допустимо ли присваивание имени глобальной переменной целиком (`state = …`), а не пути
  внутри него.
- Требование из `docs/grammar.md` §7: zero-copy строковых литералов обязывает
  подавать тот же самый исходный текст вместе со скомпилированной программой
  всякий раз, когда у неё читают литералы и имена. Дерево этот буфер не держит
  и переживать себя его не заставляет — оно хранит смещения.

До написания этой главы реализация значений и памяти невозможна. Реализация
лексера и парсера от неё не зависит.
