# Приложение C. Расхождения с ECMA-262

Нормативное приложение. Здесь регистрируется поведение принятой единицы
исполнения, отличающееся от её же поведения в JavaScript.

Расхождение отличается от сужения направлением действия. Сужение отвергает
текст: отвергнутая единица исполнения ничего не вычисляет, и всякая принятая
вычисляется всюду одинаково. Расхождение меняет результат принятого текста, а
значит требует отдельного механизма, обеспечивающего этот результат на Web.
Перечень сужений — `B-narrowings.md`; сюда они не входят.

Каждая запись содержит три части: поведение по ECMA-262, поведение по настоящей
спецификации и причина отказа от совпадения.

Расхождение принимается только тогда, когда известен механизм, обеспечивающий
определённое здесь поведение на Web. Известен — не значит изложен здесь:
механизм к языку не относится и описан в `docs/impl/`. Кандидат, для которого
механизма нет, вносится не сюда, а в приложение наследуемого поведения.

## CS-DIV-0001. Свойства прототипов недоступны

### Поведение по ECMA-262

Всякое значение, кроме `undefined` и `null`, имеет цепочку прототипов. Обращение
к свойству, отсутствующему у самого значения, продолжается по этой цепочке,
поэтому даёт не `undefined`, а унаследованное значение:

```js
({}).constructor            // функция Object
({}).toString               // функция
dict["hasOwnProperty"]      // функция
[].flat                     // функция
"abc".substring             // функция
```

### Поведение по настоящей спецификации

**CS-DIV-0001.** Обращение к свойству учитывает только собственные свойства
значения. Обращение к имени, которого у значения нет, даёт `undefined`
независимо от того, что это за имя.

Каждое из выражений выше даёт `undefined`.

Встроенные методы свойствами не являются. `items.map(...)` — операция над
массивом, определённая разделом 9 для типа Array; она не имеет значения,
доступного отдельно от вызова, и потому не наблюдается обращением к свойству:
`items.map` даёт `undefined`, а `items.map(x => x)` работает.

Следствия, разобранные в других разделах: тип Function из языка исчезает,
`typeof` не возвращает `"function"` ни для какого значения (раздел 4.1);
преобразование объекта в примитив определяется типом объекта, а не поиском
`toString` и `valueOf` (раздел 4.7).

### Причина

Объект в роли словаря — основной способ работы с пришедшим JSON, и ключи в этой
роли берутся из данных. При совпадении ключа с именем из `Object.prototype`
поведение по ECMA-262 даёт функцию там, где программа ждёт отсутствующее
значение:

```js
likes[key] ?? 0             // страховка не срабатывает: функция не nullish
```

Ошибка не диагностируется, проявляется только на конкретных данных и выглядит как
порча значения. Сужением она не закрывается: ключ вычисляемый, статически он
неизвестен.

Второе основание — стоимость модели. Цепочка прототипов существовала в языке
исключительно как механизм доставки встроенных методов, ничего сверх этого не
выражала и наружу не адресовалась. Если выбирать метод по типу получателя, как
это делает раздел 9, язык теряет только описанное выше поведение и ничего
сверх него.

### Механизм воспроизведения на Web

Поведение, определённое выше, обеспечивается на Web преобразованием исходного
текста до исполнения. Преобразование к языку не относится и описано в
`docs/impl/web-transform.md`.

## Как пополнять

Запись вносится сюда только вместе с известным механизмом. Кандидаты, для
которых механизма нет, накапливаются в `D-inherited.md` и переходят сюда при его
появлении.

Каждая запись ослабляет CS-CONF-0010 и увеличивает объём того, что на Web
приходится преобразовывать. Список должен оставаться коротким.
