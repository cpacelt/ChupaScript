# 4. Типы, значения и преобразования

Раздел определяет, из чего состоят значения языка и по каким правилам одно
значение обращается в другое. Точные результаты преобразований закрепляет
корпус тестов (раздел 11); здесь задано, какие преобразования существуют, где
они применяются и какие из их свойств проверяемы.

Определения идентификаторов не имеют. Идентификатор `CS-RT-nnnn` получает
утверждение, проверяемое подачей входа и наблюдением результата.

## 4.1. Типы

Список типов закрыт:

| Тип | Значения |
|---|---|
| Undefined | единственное значение `undefined` |
| Null | единственное значение `null` |
| Boolean | `true`, `false` |
| Number | значения двоичного формата binary64 по IEEE 754-2019 |
| String | конечные последовательности кодовых единиц UTF-16 |
| Object | изменяемые наборы свойств |

Типов Symbol, BigInt и Function в языке нет.

**CS-RT-0001.** Оператор `typeof` даёт строку по таблице:

| Значение | Результат |
|---|---|
| `undefined` | `"undefined"` |
| `null` | `"object"` |
| Boolean | `"boolean"` |
| Number | `"number"` |
| String | `"string"` |
| Object | `"object"` |

> **Пояснение.** `typeof null === "object"` — известная особенность JavaScript,
> сохранённая здесь без изменений: расхождение с ней нарушило бы CS-CONF-0010.

## 4.2. Отсутствие типа Function

Значения типа Function в языке нет, и `typeof` не даёт `"function"` ни для чего.

Функция не является значением: объявленную функцию можно вызвать по имени, но
не присвоить и не передать. Стрелочная функция существует только в позиции
аргумента встроенного метода и отдельным значением не становится. Встроенный
метод — операция над значением своего типа, а не свойство, содержащее функцию:
`items.map` даёт `undefined`, `items.map(x => x)` работает (раздел 9.1).

## 4.3. Number

Значения — двоичный формат binary64 по IEEE 754-2019. Отдельного целочисленного
типа нет: все числа принадлежат одному типу.

В множество значений входят `NaN`, `Infinity`, `-Infinity` и `-0`, отличный
от `0`.

**CS-RT-0002.** Арифметические операции выполняются с округлением
roundTiesToEven.

**CS-RT-0003.** `0 === -0` истинно, `1 / -0` даёт `-Infinity`, `String(-0)` даёт
`"0"`.

**CS-RT-0004.** `NaN === NaN` ложно. `NaN` отличается от прочих значений тем,
что не равен сам себе ни при `===`, ни при `==`.

**CS-RT-0005.** Целые значения представляются точно по модулю не свыше
2^53 − 1. За этой границей соседние целые неразличимы:
`9007199254740992 === 9007199254740993` истинно.

## 4.4. String

Значение — конечная последовательность кодовых единиц UTF-16. Кодовые точки
вне BMP представлены суррогатной парой и занимают две кодовые единицы.

**CS-RT-0006.** `length` строки — число кодовых единиц, а не кодовых точек и не
символов: `"😀".length` равно `2`.

**CS-RT-0007.** Обращение по индексу и все операции над подстроками работают в
кодовых единицах. Суррогатная пара может быть разделена, результат при этом —
корректная строка типа String, не являющаяся корректной последовательностью
UTF-16.

**CS-RT-0008.** Нормализация Unicode не применяется. Строки, состоящие из разных
последовательностей кодовых единиц, не равны, как бы ни выглядели при
отображении.

**CS-RT-0009.** Отношения `<`, `<=`, `>`, `>=` между двумя строками сравнивают
последовательности кодовых единиц лексикографически, а не по алфавиту какого-либо
языка.

## 4.5. Object

Объект — изменяемый набор свойств. Ключ свойства — значение типа String.

**CS-RT-0010.** Порядок перечисления собственных ключей: сначала ключи, являющиеся
десятичной записью целого от `0` до 2^32 − 2 без ведущих нулей, по возрастанию
числового значения; затем остальные ключи в порядке добавления. Порядок один и
тот же при перечислении любым средством языка.

> **Пояснение.** Отсюда `Object.keys({ b: 1, 2: 2, a: 3, 1: 4 })` даёт
> `["1", "2", "b", "a"]`.

**CS-RT-0011.** Массив — объект. `typeof []` даёт `"object"`; ключами элементов
служат десятичные записи индексов; `length` — обычное собственное свойство, а не
признак отдельного типа. Отличить массив от прочих объектов позволяет только
`Array.isArray`.

**CS-RT-0012.** У объекта есть только собственные свойства. Обращение к имени,
которого у объекта нет, даёт `undefined` при любом имени: `({}).constructor`,
`({}).toString` и `({}).чегоНетВовсе` неразличимы.

**CS-RT-0029.** Обращение к свойству значения `undefined` или `null` — ошибка
времени исполнения. Прочие значения получателем быть могут: обращение к
отсутствующему имени даёт `undefined` (`CS-RT-0012`), а не ошибку.

Цепочки прототипов в языке нет. Это расхождение с ECMA-262, единственное принятое;
его основание записано в приложении C (`CS-DIV-0001`), а механизм воспроизведения
на Web — в `docs/impl/`.

Отсюда `Object.keys({})` пуст, а `Object.hasOwn({}, "toString")` ложно, потому
что свойства с таким именем у объекта просто нет.

**CS-RT-0013.** Имя `__proto__` отвергается в любой форме: ключом литерала
объекта, именем при обращении, целью связывания в образце (`CS-EE-0014`).
Свойства с таким именем в языке не существует.

## 4.6. Значения и ссылки

Значения типов Undefined, Null, Boolean, Number и String неизменяемы; операции
над ними дают новые значения.

Значения типа Object изменяемы и передаются ссылкой. Присваивание, передача
аргументом и возврат копии не создают.

**CS-RT-0014.** `===` между двумя объектами истинно тогда и только тогда, когда
это один и тот же объект. Содержимое не сравнивается:
`{ a: 1 } === { a: 1 }` ложно.

## 4.7. Преобразования

Ниже определены абстрактные операции, на которые ссылаются прочие разделы.
Точные результаты закреплены корпусом тестов; здесь задано их устройство.

### ToBoolean

**CS-RT-0015.** Даёт `false` ровно для семи значений: `undefined`, `null`,
`false`, `0`, `-0`, `NaN` и пустой строки. Для всех остальных — `true`.

> **Пояснение.** В частности, `Boolean([])` и `Boolean({})` дают `true`, а
> `Boolean("0")` и `Boolean("false")` — тоже `true`: непустая строка истинна
> независимо от содержимого.

Применяется в условии `if`, в операндах `!`, `&&`, `||` и в условии тернарного
оператора. Оператор `??` ToBoolean не применяет: он различает только `undefined`
и `null`.

### ToNumber

**CS-RT-0016.** Для значений нечисловых типов:

| Вход | Результат |
|---|---|
| `undefined` | `NaN` |
| `null` | `0` |
| `false` | `0` |
| `true` | `1` |
| String | результат разбора строки как числового литерала |

**CS-RT-0017.** При разборе строки ведущие и завершающие пробелы отбрасываются;
пустая строка и строка из одних пробелов дают `0`; строка, не являющаяся
числовым литералом целиком, даёт `NaN`. Допускаются десятичная запись,
`Infinity` и префиксные записи `0x`, `0o`, `0b`. Знак `+` или `-` допустим
только перед десятичной записью и перед `Infinity`; перед префиксной записью он
даёт `NaN`. Разделитель `_` не допускается.

> **Пояснение.** Отсюда `Number("")` равно `0`, `Number(" 12 ")` равно `12`,
> `Number("12px")` — `NaN`, `Number("0x10")` равно `16`, `Number("+0x10")` —
> `NaN`, `Number("+Infinity")` — `Infinity`, `Number("1_0")` — `NaN`. Набор
> допустимых записей здесь и в продукции `NumericLiteral` (раздел 3) не
> совпадает: литерал допускает `_`, а разбор строки — нет.

Для значений типа Object сначала применяется ToPrimitive с указанием number.

### ToString

**CS-RT-0018.** Для значений нечисловых типов: `undefined` даёт `"undefined"`,
`null` — `"null"`, `true` и `false` — `"true"` и `"false"`.

**CS-RT-0019.** Для значений типа Number результат — кратчайшая десятичная
запись, которая при обратном разборе даёт исходное значение. `NaN`,
`Infinity` и `-Infinity` дают `"NaN"`, `"Infinity"`, `"-Infinity"`.

**CS-RT-0020.** Экспоненциальная форма применяется, когда десятичный порядок
значения не меньше 21 или меньше −6; в остальных случаях — позиционная.

> **Пояснение.** Отсюда `String(0.1 + 0.2)` — это `"0.30000000000000004"`,
> `String(1e21)` — `"1e+21"`, а `String(1e20)` — `"100000000000000000000"`.

Для значений типа Object сначала применяется ToPrimitive с указанием string.

### ToPrimitive

**CS-RT-0021.** Преобразует объект в значение примитивного типа. Результат
определяется типом объекта и не зависит от его свойств: свойства с именами
`toString` и `valueOf`, если программа их создала, на преобразование не влияют.

> **Пояснение.** В JavaScript то же преобразование выполняется поиском `toString`
> и `valueOf` по цепочке прототипов. Цепочки здесь нет (`CS-DIV-0001`), поэтому
> правило задано прямо. Совпадение результатов с браузером обеспечено тем, что
> создать собственное свойство с этими двумя именами язык не позволяет
> (`CS-EE-0022`): перекрыть преобразование нечем.

**CS-RT-0022.** Массив даёт строку из своих элементов, обращённых ToString и
соединённых `,`; элементы `undefined` и `null` дают пустую строку. К вложенным
массивам правило применяется рекурсивно. Объект, не являющийся массивом, даёт
`"[object Object]"`.

> **Пояснение.** Отсюда `String([1, 2])` — `"1,2"`, `String([])` — `""`,
> `String([null])` — `""`, `String([[1, 2], [3]])` — `"1,2,3"`,
> `String([{}])` — `"[object Object]"`, `String({})` — `"[object Object]"`, а
> `[1] + [2]` — `"12"`.

## 4.8. Сравнение

**CS-RT-0023.** `===` истинно, когда операнды одного типа и равны: для Object —
это один объект; для Number — равные значения, причём `NaN` не равен ничему, а
`0` и `-0` равны; для String — совпадающие последовательности кодовых единиц.

**CS-RT-0024.** `==` при операндах одного типа совпадает с `===`. При разных
типах применяется приведение по таблице:

| Пара типов | Что происходит |
|---|---|
| Null и Undefined | равны между собой и не равны ничему другому |
| Number и String | строка обращается ToNumber |
| Boolean и любой | булево обращается ToNumber |
| Object и примитив | объект обращается ToPrimitive без указания |

> **Пояснение.** Отсюда `null == undefined` истинно, `null == 0` ложно,
> `"" == 0` истинно, `"1" == true` истинно, `[] == false` истинно,
> `NaN == NaN` ложно.

**CS-RT-0025.** Отношения `<`, `<=`, `>`, `>=` при двух строках сравнивают
кодовые единицы (CS-RT-0009); в остальных случаях операнды обращаются ToNumber,
а сравнение с участием `NaN` даёт `false`.

> **Пояснение.** Отсюда `null >= 0` истинно, хотя `null == 0` ложно: отношение
> обращает `null` в `0`, а равенство — нет. Отсюда же `"10" < "9"` истинно, а
> `10 < 9` ложно.

**CS-RT-0026.** SameValueZero отличается от `===` тем, что `NaN` равен `NaN`.
Эта операция применяется методами поиска, перечисленными в разделе 9, и только
ими.

> **Пояснение.** Отсюда `[NaN].includes(NaN)` истинно, а `[NaN].indexOf(NaN)`
> даёт `-1`: `includes` использует SameValueZero, `indexOf` — `===`.
